UIcore 1.0.0

World-space menu authoring guide

A practical reference for fixed and player-relative camera menus, interactive text and item elements, state, input, animation, conditions, slots, and the public API.

Minecraft 1.20.1–26.2Paper / Folia / Purpur / LeafPacketEvents 2.14.0Updated October 4, 2026

Getting started

Put the UIcore JAR and PacketEvents in the server plugins directory. PlaceholderAPI is optional but required for external placeholders. Restart the server, then edit YAML files in plugins/UIcore/menu/.

/uicore reload
/uicore run demo_main
/uicore stop

Required

  • Paper, Folia, Purpur, or Leaf for Minecraft 1.20.1–26.2
  • Java required by the server version (17 for tested 1.20.1; 25 for 26.2)
  • PacketEvents 2.14.0

Optional

  • PlaceholderAPI
  • FancyNpcs and SkinsRestorer
  • FancyNpcsModel and BetterModel
  • CraftEngine
  • Vault and LuckPerms

Menu structure

Each YAML file may contain one top-level menu ID. Elements are declared under layout; reusable hidden definitions are declared under templates, and externally selected positions under slots.

example_menu:
  permission: ""
  wasd-enabled: false
  camera-position:
    type: player
    distance: 1.5
    offset:
      right: 0.0
      up: 0.0
      forward: 0.0
  layout:
    open_profile:
      name: "<green>Open profile"
      x: 0.0
      y: 0.2
      z: 3.5
      text-size: 0.65
      hitbox:
        width: 1.0
        height: 0.4
        depth: 0.3
      command:
        - "[message] <green>Opened"
      stop-menu:
        enabled: false
Root keyMeaning
permissionPermission required to open the menu; empty means unrestricted.
camera-positionFixed world camera or player-relative camera settings.
auto-commandsCommands executed after opening, with optional per-command delays.
wasd-enabledEnables the optional WASD selection module for this menu.
npcPer-menu NPC mirror override.
layoutVisible text, item, bar, and input elements.
templates / slotsPrepared content and dynamic display positions.

Camera, coordinates, and cursor

Element coordinates are world-space offsets in the menu camera basis. x moves right/left, y moves up/down, and z moves forward from the camera. They are not pixels. camera-position.distance places the visible cursor plane; hit-testing projects the camera ray onto each element depth, so elements may use a different z.

Fixed camera

camera-position:
  type: fixed
  world: world
  x: -187.0
  y: 100.0
  z: 347.0
  yaw: 190.0
  pitch: 0.0
  distance: 1.5

Player-relative camera

camera-position:
  type: player
  distance: 1.5
  offset:
    right: 0.0
    up: 0.0
    forward: 0.0
  yaw-offset: 0.0
  pitch-offset: 0.0

The scene anchor is captured when the menu opens. The fixed camera mechanism remains active after that. Use type: player for portable menus and fixed for authored world scenes.

Hitboxes

hitbox:
  width: 1.2
  height: 0.45
  depth: 0.3

An explicit hitbox is recommended for every button and item. Hover and left/right click use the same projected hit-test. A cursor can remain visually near the camera while interacting with content farther away.

Global cursor range

cursor-item:
  material: ARROW
  custom-model-data: 0
  scale: 0.5
  sensitivity: 1.0
  smoothing: 1.0
  max-x: 2
  max-y: 3
  movement-range:
    enabled: false
    x: { min: -2.0, max: 2.0 }
    y: { min: -3.0, max: 3.0 }
  edge-pan:
    enabled: true
    threshold: 0.78
    max-offset: { x: 0.10, y: 0.06 }
    smoothing: 0.08

max-x/max-y define rotation-to-offset scaling and the default hard cursor bounds. movement-range replaces those bounds with a custom range. The cursor stops at a boundary and never wraps to the opposite side, including when Minecraft yaw crosses +/-180 degrees. Edge pan shifts the player's client-side camera near a cursor boundary and returns it smoothly. The fixed server-side mount remains in place, so panning cannot dismount or move the player.

player-avatar, player-head, and avatar are aliases. With face-only: true, UIcore compresses the player head's depth to 2% and uses the head display transform. With billboard: center and zero tilt, the face points toward the camera without a resource pack. This is a thin head model: turning it sideways exposes its edge. Set face-only: false for a full 3D head. Use tilt to set angles in degrees; rotate: true spins a flat face in its plane or a 3D head around its vertical axis. Avatar lighting stays at full brightness. The viewer profile is available immediately. An uncached offline profile loads asynchronously.

Choose the displayed player

player accepts self, viewer, @s, a player name, UUID, or a PlaceholderAPI result resolved for the viewer. Root-level player takes precedence over avatar.player or avatar.owner. If an offline profile is not cached, UIcore requests it asynchronously and the client may show a default head until the profile is available.

Rotate or tilt the head

face-only: true scales depth to 2% while retaining the vanilla head geometry and skin layers. It is a thin 3D head, not a separate flat face texture: an oblique view can expose its edge and facial geometry. It needs no resource pack. Use face-only: false to retain the normal head depth and see the sides/back. rotate: true spins the flat face in its plane; a full head rotates about its vertical axis. rotate-speed is degrees per tick (20 ticks/second), so 0.6 is 12 degrees per second and a negative value reverses direction. With billboard: center, the face keeps turning toward the viewer; use fixed when you want to inspect its configured rotation. tilt.x/y/z adds a fixed Euler angle in degrees, in Y-X-Z composition order. Start with zero tilt and check the model in-game before adding a rotation.

An avatar is a player head rendered by an ItemDisplay. FILLED_MAP displays a map item icon; it does not turn the skin into a face image or split it across four slots. SkinsRestorer is used by the optional NPC mirror integration and is not required for a normal avatar element.

Item transform, billboard, and tilt

On type: item, transform selects the vanilla ItemDisplay model context. It selects the item's model pose; it is not an XYZ position, free-form matrix, or animation. The item's vanilla or resource-pack model determines how it looks in each context.

ValueModel contextTry it for
noneNo special display contextDefault item preview; this is the normal item's default.
guiInventory GUIA model authored as a flat inventory icon.
groundItem on the groundThe dropped item pose.
fixedItem in an item frameAn exhibit or framed icon.
headWorn on the headPlayer heads and models authored for a head slot.
third_person_left_hand, third_person_right_handThird-person handsA model authored for a held item seen by another player.
first_person_left_hand, first_person_right_handFirst-person handsA model authored for a held item seen by its wearer.

Values accept upper- or lowercase and hyphens or underscores. An unrecognized value falls back to none. material defaults to DIAMOND, custom-model-data to 0, and scale to 0.5. Match material and custom model data to the resource-pack model definition.

Billboard orientation

billboard controls how the display faces its viewer: fixed keeps its orientation, center faces the camera, horizontal rotates horizontally while preserving the vertical axis, and vertical rotates in the vertical plane. The default is center; an unknown value also falls back to center. Billboard orientation is applied alongside the model transform, so check their combination with your resource-pack model.

Tilt and continuous item spin

item_icon:
  type: item
  material: PAPER
  custom-model-data: 42
  transform: gui
  billboard: fixed
  scale: 0.8
  tilt: { x: 0, y: 0, z: 0 }
  rotate: true
  rotate-speed: 0.6
  x: 0
  y: 0
  z: 3.5
  hitbox: { width: 1.0, height: 1.0, depth: 0.35 }

tilt.x/y/z are static Euler angles in degrees; zero is no added rotation. rotate defaults to false; when enabled, rotate-speed is degrees per tick (20 ticks per second). At 0.6, the display rotates at 12 degrees per second. Negative speed reverses direction. This setting is separate from animation.type: rotate and from an avatar's face-only rotation.

Use gui, fixed, and other contexts as starting points, then inspect the exact model in the target client and resource pack. A model may intentionally use very different transforms for each context.

Styles and hover effects

Visual state priority is style → permission-style.allowed → hover-style → pressed-style → permission-style.denied. The denied style stays above hover and pressed feedback.

vip_button:
  permission: orven.vip
  name: "VIP action"
  x: 0.0
  y: 0.2
  z: 3.5
  style:
    color: "#ffd866"
  permission-style:
    allowed: { color: "#62e67a", bold: true }
    denied: { color: "#777777", strikethrough: true }
  hover-enlarge:
    enabled: true
    scale: 1.12
  hover-style:
    color: "#ffffff"
    underlined: true
    transition: { type: smooth, duration: 8 }
  pressed-style:
    text: "<green>Accepted"
    duration: 5
  hover-tooltip:
    type: actionbar
    text: "<gray>Requires <yellow>orven.vip"
  hover-cursor:
    enabled: true
    material: AMETHYST_SHARD
    custom-model-data: 0
    scale: 1.15

Style fields: text, color, bold, italic, underlined, strikethrough, and obfuscated. Smooth transition currently interpolates color; text and formatting flags switch immediately. pressed-style.text is temporary and returns after duration.

Typewriter effect

typewriter:
  enabled: true
  speed: 2
  start-delay: 0
  cursor-char: "|"

Typewriter reveals one character every speed ticks, with a minimum of one tick and default value 2. start-delay is the wait before typing begins, in ticks, default 0. cursor-char defaults to | and blinks during the delay.

Clicks, requirements, and commands

PacketEvents routes entity interaction, arm animation, and item-use packets while a menu is active. Both mouse buttons use the current cursor hit zone. Commands execute only after permission, condition, and cooldown checks pass.

Click requirements and denied response

click-requirements:
  permissions:
    - orven.profile.edit
  placeholders:
    - placeholder: "%player_world%"
      operator: "=="
      value: "world"
  denied:
    message: "<red>Action is unavailable."
    actionbar: "<gray>Check your permission and location."
    sound: minecraft:entity.villager.no
    commands:
      - "[message] <gray>Denied action"

permission-denied:
  click-behavior: deny
  message: "<red>Missing permission."
  commands:
    - "[actionbar] <yellow>This button is locked"

Cooldown

cooldown:
  key: shared_profile_action
  time: 5s
  denied:
    actionbar: "<red>Wait {cooldown.left}s"
    message: "<gray>Button is cooling down."

Toggle state and refresh

Toggle state belongs to the player's active menu session. A click changes content and style, executes the matching command list, and may refresh visibility after an external permission or placeholder change. Quote 'on' and 'off'; legacy boolean-parsed keys are also accepted.

agreement:
  name: "Agreement"
  x: 0.0
  y: 0.0
  z: 3.5
  toggle-content:
    enabled: true
    'off': "[ ] I accept"
    'on': "[x] I accept"
    on-commands:
      - "[actionbar] <green>Accepted"
    off-commands:
      - "[actionbar] <red>Cleared"
  toggle-style:
    'off': { color: "#ff6b6b", strikethrough: true }
    'on': { color: "#62e67a", bold: true }
  pressed-style:
    text: "<yellow>Switching..."
    duration: 4
  refresh-menu:
    enabled: true
    delay: 3
  stop-menu:
    enabled: false

pressed-style is momentary. toggle-content is persistent for the current session. Refresh is differential: existing displays are updated in place, newly visible elements are added, and hidden elements are removed. It never tears down the complete active menu.

Element states

Each element can define variants with states and select one with initial-state. A click on another element changes the viewer's variant through set-state or set-states.

panel:
  name: "Panel"
  x: 0
  y: 0.2
  z: 3.5
  initial-state: hidden
  states:
    hidden: { visible: false }
    shown:
      visible: true
      text: "<green>Panel open"
      style: { color: "#67e88a" }
open:
  name: "Open"
  x: 0
  y: -0.3
  z: 3.5
  set-state:
    element: panel
    state: shown

set-states: {panel: shown, badge: active} changes multiple elements; set-state: shown changes the clicked element. Variants can override visible, text, style, and item material, custom-model-data, glow. Unspecified properties inherit the base element settings. Values are per player and reset when the menu session closes. Permission checks and visible-if still apply. Try /uicore run demo_element_states.

Schematic previews

Place a Sponge .schem v2 or v3 file in plugins/UIcore/schematics/ and reference it from a menu:

schematics:
  - file: display.schem
    anchor: camera
    x: 0
    y: -1
    z: 4

camera uses integer offsets from the menu camera; world uses absolute coordinates in the menu world. The schematic's Offset is also applied. Run /uicore reload after changing files. The plugin sends block changes only to the viewer in batches of up to 512 per tick and restores current world blocks when the menu closes or switches. It never edits the world.

Each menu supports up to four files and 65,536 total blocks. Each file is limited to 8 MiB compressed and 16 MiB decompressed. Block states are shown; block entity contents, entities, and biomes are currently omitted. Unsupported block states cause that file to be skipped with a log message. Schematics do not rotate with the camera.

Visibility conditions

Hidden elements are not rendered and cannot be hovered or clicked. Conditions can use permissions, PlaceholderAPI output, player menu state, or compositions with all, any, and not.

visible-if:
  all:
    - permission: orven.menu.profile
    - placeholder: "%player_world%"
      equals: world
    - state:
        page: 2

State shorthand is also valid: visible-if: { state.page: 2 }. Comparisons include equals, not-equals, contains, not-contains, matches, greater-than, greater-or-equal, less-than, and less-or-equal.

Input fields

Any menu can capture text into a named per-player field. While a field is focused, the next chat message is cancelled, stored, and followed by a menu refresh. Use input values in element text, conditions, commands, or the API.

nickname:
  type: input-field
  name: "<yellow>Nickname: <white>{input.nickname}"
  field: nickname
  x: 0.0
  y: 0.2
  z: 3.5
  input-field:
    prompt: "<yellow>Type a nickname in chat."

submit:
  name: "Submit"
  command:
    - "[message] <green>Value: {input.nickname}"

Supported aliases include {input.nickname}, {menu.input.nickname}, %input_nickname%, and %uicore_input_nickname%. Treat values as untrusted input, especially before player or console commands.

Templates, slots, and carousel transitions

A slot displays one prepared template at its own x/y/z. UIcore renders the assignment; random rolls, perk pools, and game rules stay in a separate plugin or other automation.

templates:
  sword_from_right:
    type: item
    material: DIAMOND_SWORD
    scale: 0.7
    entrance-animation:
      enabled: true
      from: right
      duration: 12
      distance: 2.4
      easing: ease-out-back

slots:
  showcase:
    x: 0.0
    y: 0.2
    z: 3.5
    content: sword_from_right
    fallback: sword_from_right
/uicore slot set <player> <menu> <slot> <template>
/uicore slot clear|reset <player> <menu> <slot>
/uicore slot refresh <player> <menu>
/uicore slot set-global <menu> <slot> <template>
/uicore slot transition <player> <menu> <slot> <template> <direction> <ticks> [distance] [easing]

Player commands affect one viewer. Global commands affect all viewers until reload. slot transition animates the current item out, then replaces that ItemDisplay and its hitbox. The new item currently appears at its target position without a coordinated incoming animation, even when its template has entrance-animation. Account for this when designing a carousel. Other text, buttons, textures, and the cursor remain alive. The bundled item_carousel.yml provides three item templates; choose one with the UIcore slot commands or an external plugin.

Animation and dynamic coordinates

Entrance animation

entrance-animation:
  enabled: true
  from: right
  delay: 20
  duration: 12
  distance: 1.2
  easing: ease-out-back

Directions: top, bottom, left, right, front, and back. Easing: linear, ease-in-cubic, ease-out-cubic, ease-in-out-cubic, and ease-out-back. Different delay values create a staged menu entrance.

Continuous element animation

The animation block applies continuous motion to text displays and supports fade, move, rotate, scale, and bounce. The legacy floating-animation block remains compatible. It defaults to enabled when present, with speed: 1, amplitude: 0.25, and axis: y. For move, axis: x selects left-to-right motion. Speed controls the sine-wave rate in radians per second; movement amplitude is in blocks and scale amplitude is a multiplier. For ItemDisplay rotation, use rotate/rotate-speed, which is measured in degrees per tick.

animation:
  type: bounce
  speed: 1.2
  amplitude: 0.12

Dynamic coordinates

x: "map(%mmocore_level%, 1, 100, -1.5, 1.5)"
y: "0.25 * sin(t)"
z: 3.5
position-update:
  interval: 2
  smoothing: 0.15
  fallback: { x: 0.0 }
  clamp: { x: [-1.5, 1.5] }

t is elapsed seconds and ticks is elapsed server ticks. Functions include min, max, clamp, normalize, map, lerp, abs, sin, and cos. Numeric PlaceholderAPI values and {state.key} are supported. Lower smoothing values interpolate more slowly.

Navigation and menu switching

next-menu:
  enabled: true
  menu: profile_menu
stop-menu:
  enabled: true
  teleport:
    enabled: false

When the destination uses the same camera, UIcore keeps the camera and cursor session and replaces menu content without a blank frame. A different camera performs a controlled transition. stop-menu.teleport.back-original returns the player to the stored entry position; custom world coordinates are also supported.

WASD and NPC mirror

WASD navigation

Set wasd-enabled: true in a menu and enable it in wasd_config.yml. W/A/S/D select neighboring elements and Space executes the selected entry. Selection cooldown, sound, whitelist/blacklist mode, and disabled players are configurable.

Placeholders: %cmp_wasd_menu%, %cmp_wasd_enabled%, %cmp_wasd_index%, %cmp_wasd_x%, %cmp_wasd_y%, and %cmp_wasd_z%.

Per-menu NPC mirror

npc:
  enabled: true
  offset: { x: 1.4, y: 0.0, z: -2.5 }
  yaw-offset: 180
  pitch: 0
  auto-rotate: { enabled: false, speed: 1.0 }
  sync: { skin: true, equipment: true }
  name-display: { show: true, format: "<yellow>%player%" }
  custom-model:
    enabled: false
    model: merchant

FancyNpcs provides the mirror entity, SkinsRestorer can synchronize skins, and FancyNpcsModel/BetterModel can supply a custom model when installed. Missing optional plugins disable only the related integration.

Java API and events

Maven coordinates: org.orvencraft.uicore:uicore-api:1.0.0. Obtain the service through Bukkit instead of accessing plugin internals.

RegisteredServiceProvider<UIcoreApi> registration =
    Bukkit.getServicesManager().getRegistration(UIcoreApi.class);
UIcoreApi api = registration == null ? null : registration.getProvider();

api.openMenu(player, "demo_main");
api.setState(player, "demo_main", "page", "2");
api.setInput(player, "nickname", "Orven");
api.refresh(player);

API version 1.1 exposes capabilities for open/close, global and player elements, input fields, player state, refresh, events, style states, visibility, toggles, items, and slot templates.

Player and global mutations

// Visible to every viewer until reload.
api.addElement("demo_main", globalElement);
api.editElement("demo_main", "title", edit -> edit.text("Updated"));

// Visible only to this player.
api.addElement(player, "demo_main", personalElement);
api.removeElement(player, "demo_main", "personal_reward");
api.setSlot(player, "perk_menu", "left", "vampirism");

Player-scoped operations are appropriate for profiles, personal rewards, and per-player state. Global mutations affect current and future viewers in memory and are discarded by /uicore reload.

Events

MenuOpenEvent, MenuCloseEvent, MenuSwitchEvent, MenuHoverEvent, MenuClickEvent, and MenuInputEvent are fired through Bukkit. Click and input events are cancellable.

@EventHandler
public void onMenuClick(MenuClickEvent event) {
    if ("danger_button".equals(event.getElementId())) {
        event.setCancelled(true);
    }
}

Troubleshooting

  • Cursor moves but buttons do not click: verify PacketEvents, add explicit hitboxes, and use a build with projected depth hit-testing.
  • Right click does nothing: verify the active build handles PacketEvents USE_ITEM.
  • Toggle flashes then resets: quote 'on'/'off' and verify refresh uses the same active menu session.
  • Menu switch shows nothing: validate the destination ID and avoid stale stop-menu cleanup.
  • Cursor cannot reach an element: adjust max-x, max-y, sensitivity, range, or element coordinates.
  • Console command is denied: enable it explicitly and add a safe prefix to the allowlist.
  • Changes are ignored: run /uicore reload; Java code changes require a full server restart.

Камера, координаты и курсор

Координаты элемента являются смещениями в мировом базисе камеры. x двигает вправо/влево, y вверх/вниз, z вперёд от камеры. Это не пиксели. camera-position.distance задаёт плоскость видимого курсора. Для hit-test луч камеры проецируется на глубину каждого элемента, поэтому z элемента может отличаться от distance курсора.

Фиксированная камера

camera-position:
  type: fixed
  world: world
  x: -187.0
  y: 100.0
  z: 347.0
  yaw: 190.0
  pitch: 0.0
  distance: 1.5

Камера перед игроком

camera-position:
  type: player
  distance: 1.5
  offset:
    right: 0.0
    up: 0.0
    forward: 0.0
  yaw-offset: 0.0
  pitch-offset: 0.0

Позиция сцены фиксируется в момент открытия. После этого продолжает работать обычный механизм фиксированной камеры. type: player подходит для переносимых меню, fixed для сцен в конкретной точке мира.

Зоны нажатия

hitbox:
  width: 1.2
  height: 0.45
  depth: 0.3

Для каждой кнопки и предмета лучше задавать явный hitbox. Hover, левая и правая кнопка мыши используют одну проецируемую зону. Курсор может отображаться близко к камере и нажимать элементы дальше по z.

Глобальные настройки курсора

cursor-item:
  material: ARROW
  custom-model-data: 0
  scale: 0.5
  sensitivity: 1.0
  smoothing: 1.0
  max-x: 2
  max-y: 3
  movement-range:
    enabled: false
    x: { min: -2.0, max: 2.0 }
    y: { min: -3.0, max: 3.0 }
  edge-pan:
    enabled: true
    threshold: 0.78
    max-offset: { x: 0.10, y: 0.06 }
    smoothing: 0.08

max-x/max-y определяют преобразование поворота камеры в смещение и стандартные жёсткие границы курсора. movement-range заменяет их пользовательским диапазоном. У границы курсор останавливается и не переносится на противоположную сторону, в том числе при переходе yaw через +/-180 градусов. Edge pan сдвигает клиентскую камеру игрока у края доступной области и плавно возвращает её. Серверная сущность фиксированной камеры остаётся на месте, поэтому панорамирование не перемещает и не высаживает игрока.

Выберите игрока для отображения

Поле player принимает self, viewer, @s, имя игрока, UUID или результат PlaceholderAPI, разрешаемый для зрителя меню. Корневое player имеет приоритет над avatar.player и avatar.owner. Если офлайн-профиль не в кэше, UIcore запрашивает его асинхронно; пока он доступен клиенту, может отображаться стандартная голова.

Поворот и наклон головы

face-only: true сжимает глубину до 2%, сохраняя геометрию головы и слои скина. Это тонкая 3D-голова, а не отдельная плоская текстура лица: под косым углом видны край и геометрия лица. Ресурс-пак не нужен. face-only: false сохраняет объём и стороны/затылок. При rotate: true плоское лицо вращается в своей плоскости, полная голова — вокруг вертикальной оси. rotate-speed задаётся в градусах за тик (20 тиков/секунду): 0.6 — это 12 градусов в секунду; отрицательная скорость меняет направление. При billboard: center лицо постоянно разворачивается к зрителю; попробуйте fixed, если нужно проверить заданный поворот. tilt.x/y/z задают постоянные углы, которые складываются в порядке Y-X-Z. Начните с нулевого наклона и проверьте модель в игре.

Пример: кликабельный портрет зрителя

avatar:
  type: player-avatar

Аватар — голова игрока через ItemDisplay. FILLED_MAP показывает значок карты и не превращает скин в картинку лица или портрет из четырёх display. SkinsRestorer применяется в дополнительной интеграции с NPC и не нужен обычному аватару.

Для type: item значение transform выбирает стандартный контекст модели ванильного ItemDisplay. Это поза модели предмета, а не координаты XYZ, произвольная матрица или анимация. Ванильная модель или ресурспак определяют её вид в каждом контексте.

Ориентация billboard

fixed закрепляет ориентацию display, center направляет к камере, horizontal поворачивает по горизонтали и сохраняет вертикальную ось, vertical поворачивает в вертикальной плоскости. По умолчанию center; неизвестное значение также использует его. Billboard применяется вместе с transform модели, поэтому проверяйте это сочетание с ресурспаком.

Наклон и непрерывное вращение

item_icon:
  type: item
  material: PAPER
  custom-model-data: 42
  transform: gui
  billboard: fixed
  scale: 0.8
  tilt: { x: 0, y: 0, z: 0 }
  rotate: true
  rotate-speed: 0.6
  x: 0
  y: 0
  z: 3.5
  hitbox: { width: 1.0, height: 1.0, depth: 0.35 }

tilt.x/y/z — статические углы в градусах; ноль не добавляет поворот. rotate по умолчанию выключен. При включении rotate-speed задаётся в градусах за тик: 0.6 даёт 12 градусов в секунду, отрицательное значение разворачивает вращение. Это отдельная настройка от animation.type: rotate и вращения плоского аватара.

Попробуйте gui, fixed или другой контекст, а затем посмотрите на ту же модель в целевом клиенте с нужным ресурспаком. Одна модель может иметь разные преобразования для каждого контекста.

Клики, проверки и команды

Во время меню PacketEvents обрабатывает interact entity, взмах рукой и использование предмета. Обе кнопки мыши работают по текущему hitbox курсора. Команды выполняются только после проверок permission, условий и cooldown.

Проверки клика и отказ

click-requirements:
  permissions:
    - orven.profile.edit
  placeholders:
    - placeholder: "%player_world%"
      operator: "=="
      value: "world"
  denied:
    message: "<red>Действие недоступно."
    actionbar: "<gray>Проверьте право и местоположение."
    sound: minecraft:entity.villager.no
    commands:
      - "[message] <gray>Клик отклонён"

permission-denied:
  click-behavior: deny
  message: "<red>Нет нужного права."
  commands:
    - "[actionbar] <yellow>Кнопка заблокирована"

Cooldown

cooldown:
  key: shared_profile_action
  time: 5s
  denied:
    actionbar: "<red>Подождите {cooldown.left}s"
    message: "<gray>Кнопка на перезарядке."

Toggle и обновление

Toggle-состояние принадлежит сессии меню конкретного игрока. Клик меняет содержимое и стиль, выполняет подходящий список команд и может обновить видимость после изменения permission или placeholder. Ключи 'on' и 'off' лучше брать в кавычки; старые boolean-ключи также поддерживаются.

agreement:
  name: "Соглашение"
  x: 0.0
  y: 0.0
  z: 3.5
  toggle-content:
    enabled: true
    'off': "[ ] Я согласен"
    'on': "[x] Я согласен"
    on-commands:
      - "[actionbar] <green>Принято"
    off-commands:
      - "[actionbar] <red>Отменено"
  toggle-style:
    'off': { color: "#ff6b6b", strikethrough: true }
    'on': { color: "#62e67a", bold: true }
  pressed-style:
    text: "<yellow>Переключение..."
    duration: 4
  refresh-menu:
    enabled: true
    delay: 3
  stop-menu:
    enabled: false

pressed-style действует временно, а toggle-content хранит состояние в текущей сессии. Refresh работает дифференциально: существующие display обновляются на месте, ставшие видимыми элементы добавляются, а скрытые удаляются. Полный teardown открытого меню не выполняется.

Состояния элементов

Элемент задаёт варианты в states и начальное значение в initial-state. Нажатие другого элемента меняет вариант для конкретного игрока через set-state или set-states.

panel:
  name: "Панель"
  x: 0
  y: 0.2
  z: 3.5
  initial-state: hidden
  states:
    hidden: { visible: false }
    shown:
      visible: true
      text: "<green>Панель открыта"
      style: { color: "#67e88a" }
open:
  name: "Открыть"
  x: 0
  y: -0.3
  z: 3.5
  set-state:
    element: panel
    state: shown

set-states: {panel: shown, badge: active} меняет несколько элементов; set-state: shown меняет элемент, на который нажали. Вариант может переопределить visible, text, style, а для предмета — material, custom-model-data, glow. Остальные свойства наследуются. Состояния независимы для каждого игрока и сбрасываются при закрытии меню. Permission и visible-if продолжают действовать. Пример: /uicore run demo_element_states.

Показ схем

Поместите Sponge .schem версии 2 или 3 в plugins/UIcore/schematics/ и укажите его в меню:

schematics:
  - file: display.schem
    anchor: camera
    x: 0
    y: -1
    z: 4

camera задаёт целочисленные смещения от камеры меню; world — абсолютные координаты в мире меню. Смещение Offset файла также применяется. После изменения файлов выполните /uicore reload. Плагин отправляет блоки только смотрящему игроку порциями до 512 за тик и восстанавливает актуальные блоки мира при закрытии или смене меню. Настоящий мир не изменяется.

Меню может ссылаться максимум на четыре файла и 65 536 блоков суммарно. Размер файла ограничен 8 МиБ сжатых и 16 МиБ распакованных данных. Сейчас показываются состояния блоков без содержимого block entities, сущностей и биомов. Неподдерживаемые блоки приводят к пропуску файла с записью в журнале. Схема не вращается вместе с камерой.

Условия видимости

Скрытый элемент не создаётся и не получает hover/click. Условия используют permission, PlaceholderAPI, локальное состояние меню и композиции all, any, not.

visible-if:
  all:
    - permission: orven.menu.profile
    - placeholder: "%player_world%"
      equals: world
    - state:
        page: 2

Допустима короткая форма visible-if: { state.page: 2 }. Сравнения: equals, not-equals, contains, not-contains, matches, greater-than, greater-or-equal, less-than, less-or-equal.

Поля ввода

Любое меню может записать текст в именованное поле конкретного игрока. Пока поле в фокусе, следующее сообщение чата отменяется, сохраняется и вызывает обновление меню. Значение доступно в тексте, условиях, командах и API.

nickname:
  type: input-field
  name: "<yellow>Ник: <white>{input.nickname}"
  field: nickname
  x: 0.0
  y: 0.2
  z: 3.5
  input-field:
    prompt: "<yellow>Введите ник в чат."

submit:
  name: "Отправить"
  command:
    - "[message] <green>Значение: {input.nickname}"

Псевдонимы: {input.nickname}, {menu.input.nickname}, %input_nickname%, %uicore_input_nickname%. Считайте input недоверенными данными, особенно перед player/console-командами.

Шаблоны, слоты и карусель

Слот показывает один подготовленный template в собственных x/y/z. UIcore только отображает назначение; рандом, пулы перков и игровые правила остаются во внешнем плагине или другой автоматизации.

templates:
  sword_from_right:
    type: item
    material: DIAMOND_SWORD
    scale: 0.7
    entrance-animation:
      enabled: true
      from: right
      duration: 12
      distance: 2.4

slots:
  showcase:
    x: 0.0
    y: 0.2
    z: 3.5

/uicore slot transition <player> <menu> <slot> <template> <direction> <ticks> [distance] [easing]

Player-команды влияют на одного зрителя, global-команды на всех до reload. slot transition анимирует уход текущего предмета, затем заменяет его ItemDisplay и hitbox. Сейчас новый предмет появляется в целевой позиции без согласованной входящей анимации, даже когда в template задан entrance-animation. Учитывайте это при создании карусели. Остальной текст, кнопки, текстуры и курсор продолжают существовать. Три заготовки находятся в item_carousel.yml; выбрать их можно командой UIcore или внешним плагином.

Анимации и динамические координаты

Анимация появления

  enabled: true
  from: right
  delay: 20
  duration: 12
  distance: 1.2
  easing: ease-out-back

Направления: top, bottom, left, right, front, back. Easing: linear, ease-in-cubic, ease-out-cubic, ease-in-out-cubic, ease-out-back. Разные delay позволяют выводить элементы по очереди.

Постоянная анимация элемента

Блок animation поддерживает fade, move, rotate, scale, bounce. Старый floating-animation остаётся совместимым.

  type: bounce
  speed: 1.2
  amplitude: 0.12

Динамические координаты

x: "map(%mmocore_level%, 1, 100, -1.5, 1.5)"
y: "0.25 * sin(t)"
z: 3.5
position-update:
  interval: 2
  smoothing: 0.15
  fallback: { x: 0.0 }
  clamp: { x: [-1.5, 1.5] }

t означает прошедшие секунды, ticks прошедшие серверные тики. Функции: min, max, clamp, normalize, map, lerp, abs, sin, cos. Поддерживаются числовые PlaceholderAPI и {state.key}. Чем меньше smoothing, тем медленнее интерполяция.

Навигация и переходы

  enabled: true
  menu: profile_menu

  teleport:

Решение проблем

  • Курсор двигается, кнопки не нажимаются: проверьте PacketEvents, задайте hitbox и используйте билд с проекцией hit-test по глубине.
  • Правая кнопка не работает: активный билд должен обрабатывать PacketEvents USE_ITEM.
  • Toggle мигает и сбрасывается: возьмите 'on'/'off' в кавычки и убедитесь, что refresh сохраняет текущую сессию.
  • После перехода нет нового меню: проверьте ID назначения и устаревший cleanup из stop-menu.
  • Курсор не достигает элемента: настройте max-x, max-y, sensitivity, range или координаты элемента.
  • Console-команда отклонена: явно включите её и добавьте безопасный префикс в allowlist.
  • Изменения не применились: выполните /uicore reload; изменения Java требуют полного рестарта.

Полный справочник автора меню

Это справочник по YAML-меню UIcore: от размещения камеры и настройки модели предмета до условий, состояний, анимаций и связей экранов. Значения и примеры сверены с текущей реализацией плагина. Если параметр не указан, применяется описанное ниже значение по умолчанию.

1. Установка, файлы и перезагрузка

Положите UIcore и PacketEvents в plugins/, запустите сервер, а затем редактируйте меню в plugins/UIcore/menu/*.yml. PacketEvents обязателен. PlaceholderAPI нужен для %...%, проверок по PlaceholderAPI и плейсхолдеров игроков/скинов; без него меню с такими проверками не пройдут их проверку. FancyNpcs нужен для зеркального NPC; FancyNpcsModel вместе с поддерживаемым провайдером модели — для пользовательской модели NPC; SkinsRestorer — для получения скина в NPC-интеграции; CraftEngine — для его тегов <image:...> и <shift:...>. Это дополнительные возможности, а не обязательные зависимости для обычных меню.

Меню поддерживаются на Paper, Folia, Purpur и Leaf для Minecraft 1.20.1–26.2 при наличии подходящей сборки сервера. Требуемая версия Java зависит от сборки Minecraft.

/uicore reload             # перечитать меню и файлы настроек
/uicore run demo_main      # открыть меню себе
/uicore run demo_main Nick # открыть меню онлайн-игроку (нужны права)
/uicore stop               # закрыть своё меню

Идентификатор меню — верхний ключ YAML; он должен быть уникальным среди всех файлов. Файл может содержать несколько меню. В каждом меню обязателен camera-position. Удалите или исправьте ошибочную конфигурацию, если после reload в журнале есть ошибка разбора: некорректный YAML остановит загрузку этого меню.

Готовые меню из поставки: demo_main, demo_conditions, demo_styles, demo_toggle_input, demo_element_states, demo_dynamic_position, demo_player_avatar, demo_slots, demo_entrance_npc, demo_items_api, item_carousel и другие demo_*.yml.

2. Минимальная структура меню

welcome:
  permission: ""           # пусто: открытие не ограничено
  wasd-enabled: false
  camera-position:
    type: player
    distance: 1.5
  layout:
    title:
      name: "<gold><bold>Добро пожаловать"
      x: 0
      y: 0.8
      z: 3.5
      text-size: 0.7
    close:
      name: "<red>Закрыть"
      x: 0
      y: -0.8
      z: 3.5

        teleport:

layout — отображаемые элементы. templates — определения для слотов, сами по себе они не появляются на экране. slots — позиции, в которые UIcore подставляет шаблоны по указанию меню, команды, Java API или внешнего плагина. Все координаты элементов и слотов задаются относительно камеры в блоках, а не в пикселях.

3. Камера, координаты и курсор

Положение камеры

camera-position.type (устаревший совместимый псевдоним — mode) принимает fixed или player; по умолчанию fixed. Для fixed задайте world, x, y, z, yaw, pitch. Мир по умолчанию — world, числа — 0; distance по умолчанию 1.5. Мир должен существовать.

camera-position:
  type: fixed
  world: world
  x: -187.0
  y: 100.0
  z: 347.0
  yaw: 190
  pitch: 0
  distance: 1.5

При type: player меню строится от положения и направления игрока в момент открытия. offset.right, offset.up, offset.forward (синонимы x/y/z) задают сдвиг относительно направления игрока; по умолчанию все нулевые. yaw-offset и pitch-offset также по умолчанию 0.

В основном config.yml есть use-player-location. Когда он включён, камера из меню игнорируется и применяется позиция игрока. В этом же файле настраивается курсор, его диапазон и краевой сдвиг камеры.

Базис координат элементов

  • x: вправо/влево относительно камеры.
  • y: вверх/вниз.
  • z: вперёд от камеры. Обычно положительное z размещает сцену перед игроком.

Эти оси поворачиваются вместе с направлением фиксированной камеры. camera-position.distance — расстояние курсорной плоскости от камеры, а не z элемента. Клик проверяется лучом курсора на глубине элемента, поэтому видимая плоскость курсора и координата z кнопки могут различаться.

Число можно заменить формулой динамической позиции; см. раздел «Формулы координат».

Общие настройки курсора (config.yml)

Настройки курсора действуют на сервере, поэтому влияют на все меню:

Путь Значение по умолчанию Назначение
cursor-item.material ARROW Материал визуального курсора
cursor-item.custom-model-data 0 Модель курсора из ресурспака
cursor-item.scale 0.5 Основной размер
cursor-item.sensitivity 1.0 Умножитель перемещения
cursor-item.smoothing 1.0 1 — без задержки; меньше — плавнее, но медленнее
cursor-item.size.x/y/z 1.0 Множитель размера по каждой оси
cursor-item.max-x, max-y 2, 3 Масштаб преобразования поворота камеры в смещение и предел курсора по умолчанию
cursor-item.x, y, z-offset 0 Начальный сдвиг курсора относительно плоскости меню

movement-range.enabled: true задаёт явные пределы x.min/max и y.min/max в локальных координатах камеры вместо границ max-x/max-y. По умолчанию выключено; пределы по умолчанию [-2, 2] и [-3, 3]. Курсор упирается в край и не переносится на противоположный край.

default-position.enabled: true задаёт начальные x/y курсора при открытии. По умолчанию выключено: используются cursor-item.x/y.

edge-pan.enabled по умолчанию включён. Он слегка перемещает клиентскую камеру, когда курсор подходит к краю: threshold: 0.78, max-offset.x: 0.10, max-offset.y: 0.06, smoothing: 0.08. Сдвиг ограничен указанными смещениями, начинается после порога и сглаженно возвращается к центру. Это прокрутка вида камерой; она не меняет координаты элементов и не создаёт динамический наклон (tilt).

4. Типы элементов и общие поля

Любой элемент задаётся под layout и использует ключ как внутренний ID:

layout:
  play:
    type: text                # по умолчанию text
    name: "<green>Играть"
    x: 0
    y: 0
    z: 3.5
    text-size: 1.0
Тип Назначение и основные поля
text или тип по умолчанию Текстовая надпись или кнопка: name, text-size, tilt
item ItemDisplay: material, custom-model-data, scale, transform, billboard, rotate
player-avatar Скин-голова игрока: player, face-only, scale, transform, billboard, rotate
bar-text Полоска, собранная из текстовых символов: value, max, segments
input-field Текстовый элемент, который выбирает поле для следующего ввода в чат: field, input-field.prompt

Псевдонимы аватара: player-avatar, player-head, avatar. Не задавайте interactive или type: panel: таких режимов YAML-элемента нет. Декоративная надпись тоже получает хитбокс; при необходимости задайте ему небольшие размеры.

Общие поля:

Путь Значение по умолчанию Назначение
name ID элемента Текст элемента; допускает MiniMessage, плейсхолдеры и /n для новой строки
x, y, z 0 Координаты относительно камеры, числа или формулы
text-size 1.0 Размер отображения текста; влияет и на размер текстового хитбокса
tilt.x/y/z 0° Постоянный наклон display вокруг локальных осей

Для обычного текста автоматический хитбокс примерно рассчитывается по числу видимых символов, высота около 0.2, глубина около 0.05; масштабируется text-size. Для текста можно указать точные width, height, depth. Для предмета область по умолчанию около его scale по ширине и высоте, глубина 0.25. Явный hitbox заменяет расчётный. Например, предмету часто полезно задать область шире и глубже самого визуального значка:

hitbox:
  width: 0.9
  height: 0.9
  depth: 0.4

Поля hitbox.text и hitbox.display не нужны для обычного hitbox; задавайте числовые ширину, высоту и глубину. Для элементов, расположенных близко друг к другу, уменьшите хитбоксы так, чтобы области не перекрывались. Проверяются и левый, и правый клик.

5. Предметы: transform, billboard и tilt

В type: item поле transform задаёт стандартный ванильный ItemDisplayTransform, то есть контекст модели предмета, для которого игра берёт поворот/смещение модели. Это не координаты, не произвольная матрица и не анимация. Ресурспак и модель предмета могут по-разному выглядеть в каждом контексте.

transform Контекст ванильной модели Когда пробовать
none Без специального контекста; значение обычного предмета по умолчанию Предмет как предметный значок или простая 3D-модель
gui Модель для инвентарного интерфейса Плоская иконка, нарисованная в модели для GUI
ground Предмет, лежащий на земле Вид как у выброшенного/лежащего предмета
fixed Предмет в рамке Значок или модель в виде размещённого экспоната
head Предмет надет на голову Головы и модели, сделанные для ношения на голове
third_person_left_hand Левая рука от третьего лица Модель, настроенная для третьего лица
third_person_right_hand Правая рука от третьего лица Модель, настроенная для третьего лица
first_person_left_hand Левая рука от первого лица Модель, настроенная для первого лица
first_person_right_hand Правая рука от первого лица Модель, настроенная для первого лица

Можно писать значения в верхнем регистре и с дефисами или подчёркиваниями. Неизвестное значение откатывается к none. Пример:

portrait_item:
  type: item
  material: PAPER
  custom-model-data: 42
  transform: gui
  billboard: fixed
  scale: 0.8
  tilt: { x: 0, y: 0, z: 0 }
  x: 0
  y: 0
  z: 3.5
  hitbox: { width: 1.0, height: 1.0, depth: 0.35 }

scale задаёт общий размер модели (по умолчанию 0.5). custom-model-data — целое число от 0, по умолчанию 0. material — материал сервера, по умолчанию DIAMOND; его имя должно быть допустимо в версии сервера. Для ресурспаковой модели материал и custom model data должны соответствовать её настройке.

Старые/вложенные настройки предмета поддерживаются под item:: например, item.material, item.custom-model-data, item.scale, item.glow, item.rotate, item.rotate-speed, item.billboard, item.transform. Если ключ одновременно указан в корне элемента и внутри item:, выигрывает корневой ключ. Для нового YAML проще держать их на одном уровне с type: item.

billboard определяет, как display поворачивается относительно зрителя: fixed оставляет ориентацию закреплённой; center разворачивает к камере; horizontal сохраняет вертикаль и поворачивается по горизонтали; vertical поворачивается в вертикальной плоскости. По умолчанию center; неизвестное значение также использует center. На предметном ресурспаке проверьте сочетание transform, billboard и наклона визуально: billboard может добавлять ориентацию относительно зрителя поверх контекста модели.

tilt.x/y/z — углы в градусах, нулевое значение не добавляет наклон. Укажите секцию tilt с нужными компонентами. Наклон меняет ориентацию элемента постоянно и сам по себе не следует за курсором.

Поле Значение по умолчанию Что меняет
rotate false Непрерывное вращение ItemDisplay
rotate-speed 1.0 Градусы за тик (20 тиков/с); отрицательное значение меняет направление
glow false Подсветка предмета
billboard center Ориентация display относительно камеры

Скорость вращения предмета измеряется в градусах за тик: 1 — 20 градусов в секунду. Если используете ресурс-пак, одна и та же модель может выглядеть по-разному при gui, ground, fixed и видах от первого/третьего лица. Подберите контекст модели в Minecraft, затем задайте те же имя контекста здесь.

6. Аватар игрока: лицо, полный объём, владелец и поворот

Аватар — это скин игрока, показанный стандартной головой PLAYER_HEAD через ItemDisplay. Миниатюра не требует ресурс-пака. Если нужный профиль уже есть в кэше, скин отображается сразу; отсутствующий офлайн-профиль может загружаться асинхронно. Клиент игрока тоже должен получить скин по обычному механизму Minecraft.

avatar:
  type: player-avatar
  player: self
  face-only: true
  scale: 0.9
  transform: head
  billboard: center
  rotate: false
  rotate-speed: 0.6
  tilt: { x: 0, y: 0, z: 0 }
  x: 0
  y: 0.15
  z: 3.5
  hitbox: { width: 0.9, height: 0.9, depth: 0.4 }
  hover-tooltip:
    type: actionbar
    text: "<gray>Ваш скин"
  command:
    - "[message] <green>Открываем профиль"
  stop-menu:
    enabled: false
Путь Значение по умолчанию Как работает
type — Используйте player-avatar, player-head или avatar
player self Чей скин отображать
face-only false При true сжимает глубину головы до 2% её размера
scale 0.5 Размер головы по ширине и высоте
transform head Контекст модели по умолчанию для аватара
billboard center Направляет лицо к камере
rotate false Вращение по вертикальной оси для объёмной головы; в плоском режиме лицо крутится в своей плоскости
rotate-speed 1.0 Градусы за тик; 0.6 — 12°/с
tilt.x/y/z 0° Дополнительный фиксированный наклон
glow false Подсветка отображения
hitbox ширина/высота по scale, глубина 0.25 Настраиваемая область наведения/клика

player понимает self, viewer, @s, имя игрока, UUID или результат PlaceholderAPI. Плейсхолдер разрешается для зрителя меню. Корневое player имеет приоритет над вложенным avatar.player/avatar.owner, если задано одновременно. Вложенная форма поддерживается, но для читаемости удобнее располагать настройки аватара в корне:

avatar:
  type: player-avatar
  player: "%someplugin_profile_owner%"
  face-only: false

При face-only: true геометрия головы сохраняется, но глубина модели становится очень малой. Это показывает переднюю поверхность скина без текстуры-накладки; под сильным углом всё ещё видны тонкий край и поверхности геометрии головы. Значение false сохраняет 3D-объём и позволяет видеть стороны/затылок. Отдельная плоская текстура лица не создаётся. Настройки наклона аватара применяются в градусах вокруг локальных осей; для привычного вида начинайте с нулевых tilt и billboard: center.

avatar_spin:
  type: avatar
  player: viewer
  face-only: true
  billboard: fixed
  rotate: true
  rotate-speed: 0.6
  x: 0
  y: 0
  z: 3.5

Плоский аватар при rotate: true вращается как лицо в плоскости, а объёмная голова вращается вокруг вертикальной оси. При billboard: center лицо постоянно разворачивается к камере; если нужен демонстрационный оборот, попробуйте fixed и проверьте положение скина в своей версии клиента. Аватар освещается на полной яркости. SkinsRestorer относится к интеграции зеркального NPC, а не обязателен для обычного аватара игрока.

Не путайте аватар с картинкой карты. material: FILLED_MAP показывает модель/значок предмета карты. Он не превращает skin в четырёхслотовый портрет. transform также не разбивает голову на несколько display-элементов.

7. Текст, цвет, MiniMessage и перенос строки

В name, текстах состояний, подсказках и сообщениях можно использовать MiniMessage, например <gold>, <#77aaff>, <bold>, <underlined>, <click:...>. Старый формат &a тоже поддерживается. Если в строке есть валидный MiniMessage-тег, она разбирается как MiniMessage. В обычных текстах display теги событий чата не превращают надпись в ссылку; используйте link или сообщение в чат, если нужна открываемая ссылка.

Новая строка записывается как /n:

name: "<gray>Первая строка/nВторая строка</gray>"

YAML не интерпретирует /n как escape-последовательность; UIcore преобразует его в перенос. Также можно заключить строку в кавычки и использовать многострочный YAML, если это требуется парсеру. Для проверки цвета не помещайте ярлыки в глобальный style.color, когда часть текста уже должна иметь свой цвет: заданный стиль может перекрыть цвета отдельных фрагментов.

CraftEngine добавляет специальные теги <image:...> и <shift:...> только при установленном совместимом CraftEngine.

Обычный текст выводится TextDisplay с прозрачным фоном, тенью и billboard center. Эти параметры текста не настраиваются в YAML элемента. Секция billboard относится к ItemDisplay предмета/аватара; текстовые элементы всегда смотрят на зрителя.

Стили и порядок наложения

Доступные ветки: style, permission-style.allowed, toggle-style.on/off, стиль активного states.<id>.style, hover-style, pressed-style, permission-style.denied. Они последовательно накладываются; если один и тот же параметр задан в нескольких ветках, применяется более поздний: обычный → разрешённое право → toggle → состояние элемента → наведение → нажатие → отказ по permission. Неуказанные поля наследуются. Отказной стиль может оставаться поверх hover/pressed, если у игрока нет права.

style:
  color: "#83aaff"
  bold: false
  italic: false
  underlined: false
  strikethrough: false
  obfuscated: false
hover-style:
  color: "#ffffff"
  underlined: true
  transition:
    type: smooth
    duration: 8
permission-style:
  allowed: { color: "#62e67a" }
  denied: { color: "#777777", strikethrough: true }

underlined также называется underline, strikethrough — strike, obfuscated — magic. Плавный переход применяется к цвету hover; текст и булевы украшения меняются сразу. hover-enlarge.enabled включает увеличение, scale по умолчанию 1.2.

Другие поля обратной связи:

  • hover-cursor.enabled по умолчанию включён, если секция задана. Нужен допустимый material; можно указать custom-model-data (по умолчанию 0) и scale. Без размера применяется размер из общего config.yml.
  • hover-tooltip.type: actionbar по умолчанию; можно выбрать chat/message. text задаёт содержание подсказки.
  • hover-sound: name, volume: 1, pitch: 1, cooldown: 20 тиков (минимум 5).
  • hover-commands запускаются при наведении, leave-commands — при уходе курсора.
  • pressed-style.duration задаётся в тиках, по умолчанию 3; его text временно заменяет подпись.

У текстовой надписи можно включить эффект печатной машинки:

typewriter:
  enabled: true
  speed: 2
  start-delay: 0
  cursor-char: "|"

Эффект применим к TextDisplay, включая кнопки. speed — число тиков на один символ, минимум 1, по умолчанию 2; start-delay — пауза перед набором в тиках, по умолчанию 0; cursor-char по умолчанию |. Во время паузы курсор мигает.

8. Клики, права, условия и сообщения об отказе

Для клика должны пройти проверки меню/элемента, видимости, click-requirements, устаревшего condition (если задан), и cooldown. Только после них запускается обычное действие. Permission элемента скрывает кнопку? Нет: оно ограничивает действие клика и позволяет показать пользователю состояние через permission-style/permission-denied. Для полного скрытия используйте visible-if.

Permission для меню и элемента

my_menu:
  permission: server.menu.open
  camera-position: { type: player, distance: 1.5 }
  layout:
    vip:
      permission: server.vip
      name: "<gold>Премиум"
      x: 0
      y: 0
      z: 3.5
      permission-style:
        denied: { color: "#777777", strikethrough: true }
      permission-denied:
        click-behavior: deny
        message: "<red>Нужна привилегия VIP"
        actionbar: "<gray>Откройте страницу магазина"
        sound: minecraft:entity.villager.no
        volume: 1
        pitch: 1
        commands: []

У меню пустое право по умолчанию; у элемента оно также пустое. OP проходит permission-проверки. permission-denied.click-behavior: ignore подавляет ответ отказа. permission-denied настраивает текст чата, action bar, звук, громкость/тон и список команд при отказе.

Требования именно к клику

click-requirements:
  permissions:
    - server.profile.edit
  placeholders:
    - placeholder: "%player_world%"
      operator: equals
      value: world
  denied:
    message: "<red>Сначала войдите в основной мир"
    actionbar: "<gray>Действие недоступно"
    sound: minecraft:entity.villager.no
    volume: 1
    pitch: 1
    commands: []

Все permissions и placeholders внутри click-requirements должны пройти проверку. Для плейсхолдеров доступны ==, !=, >, >=, <, <= или названия equals, not-equals, greater-than, greater-or-equal, less-than, less-or-equal. Числовые операторы требуют числовое значение. Неразрешённый плейсхолдер или недоступный PlaceholderAPI означает отказ. Сообщения отказа можно задать в click-requirements.denied; иначе используется ответ отказа permission, если он задан.

Старый краткий condition.variable/operator/value тоже доступен и требует PlaceholderAPI. Для нового YAML предпочтительнее click-requirements или visible-if, потому что они яснее различают показ и действие.

Условия показа visible-if

Условие показа применяется независимо от permission и не выдаёт права на клик. Отключённый состоянием или visible-if элемент не рисуется и не выбирается курсором. Простая строка означает permission. Поддерживаются permission, placeholder, state и композиции all, any, not:

visible-if:
  all:
    - permission: server.profile
    - placeholder: "%player_world%"
      equals: world
    - state:
        page: "2"

Сокращение для одного значения: visible-if: { state.page: "2" }. all — все дочерние условия, any — любое, not — инверсия одного. state здесь — строковый объект данных меню, например записанный другой логикой/API; это не states внешнего вида элемента. Для placeholder доступны equals, not-equals, contains, not-contains, matches, greater-than, greater-or-equal, less-than, less-or-equal и operator + value. matches использует безопасный regex, ограниченный длиной выражения 256 и входного текста 1024 символами. Напишите value строкой в кавычках, если там число с ведущим нулём или YAML может распознать boolean.

9. Элементные состояния и toggle — разные вещи

states: выбор варианта элемента

states заменяет у одного элемента visible, текст, стиль, а для type: item ещё material, custom-model-data и glow. Координаты, тип, хитбокс, вращение, permission и команды остаются из основного определения. initial-state должен ссылаться на существующий ключ states. Если не задан, берётся состояние с именем default, если оно есть, иначе первый элемент в YAML.

layout:
  panel:
    name: "<gray>Профиль закрыт"
    x: 0
    y: 0.2
    z: 3.5
    hitbox: { width: 1.6, height: 0.8, depth: 0.3 }
    initial-state: closed
    states:
      closed:
        visible: false
      open:
        visible: true
        text: "<green>Статистика\n<gray>Побед: 17"
        style: { color: "#70ee91" }
  open_button:
    name: "<yellow>Профиль"
    x: 0
    y: -0.7
    z: 3.5
    hitbox: { width: 1.2, height: 0.45, depth: 0.3 }
    set-state: { element: panel, state: open }
    stop-menu:
      enabled: false

set-state: open меняет собственное состояние на open; форма { element: panel, state: open } указывает цель. set-states: { panel: open, badge: active } меняет несколько. При одновременном использовании одного ключа значение из set-states имеет приоритет. Цель и имя варианта должны существовать.

Варианты хранятся для игрока в меню и очищаются при закрытии. Команда, которая нажата и сама меняет состояние, также требует своего hitbox, как любая кнопка. visible-if и permission продолжают работать независимо: состояние visible: true не обходит отдельное условие. Используйте states, чтобы открыть/скрыть или переименовать связанный элемент, не связывая это с permission.

toggle-content: переключатель на самой кнопке

Toggle меняет текст и стиль на одной кнопке, выполняет on-commands или off-commands и может обновлять меню. Начально выключен; включён в сессию игрока и сбрасывается при закрытии. on и off в YAML обязательно лучше писать в кавычках, иначе парсер может принять их за boolean.

toggle:
  name: "Скрывать сообщения"
  x: 0
  y: 0
  z: 3.5
  toggle-content:
    enabled: true
    'off': "[ ] Скрывать сообщения"
    'on': "[x] Скрывать сообщения"
    on-commands: ["[actionbar] <green>Включено"]
    off-commands: ["[actionbar] <red>Выключено"]
  toggle-style:
    'off': { color: "#ff6b6b" }
    'on': { color: "#62e67a", bold: true }
  refresh-menu: { enabled: true, delay: 3 }

Также принимаются старые псевдонимы before/after, commands-on/commands-off. toggle-content — переключатель своего текста и отдельный от states механизм; он не меняет видимость другого элемента.

10. Задержка, cooldown, случайные команды и навигация

Команды по клику

Команда элемента может иметь один из префиксов:

Префикс Кто выполняет Примечание
без префикса или [player] игрок Поведение по умолчанию
[console] консоль security.allow-console-commands: false по умолчанию; нужно включить и настроить allowlist в config.yml
[op] игрок, только если он уже OP Временный OP не выдаётся; параметр безопасности выключен по умолчанию
[message] UIcore отправляет сообщение Поддерживает MiniMessage
[actionbar] UIcore отправляет action bar Поддерживает MiniMessage
[server] UIcore отправляет BungeeCord plugin message Нужны поддерживающий proxy и настройка перехода 
command:
  - "[message] <green>Нажатие принято"
  - "<delay=40>[player] spawn"

<delay=N> указывает задержку конкретной команды в тиках; без него применяется command-delay. Если command-delay не задан, команда выполняется сразу. Для секции auto-commands.delays — задержки в тиках, по одной на команду; если задержка для индекса не указана, UIcore использует 20 тиков. Повторный клик блокируется на время обработки около одного тика.

На клике также можно задать random-commands и список random-chances. Выбор использует веса из списка random-chances, длины списков должны совпадать. Если веса не нужны, укажите только random-commands для равновероятного выбора. Не полагайтесь на альтернативные синтаксисы списка.

Команды получают стандартные значения %player%, %player_name%, %player_uuid%, %player_displayname%, %player_x%, %player_y%, %player_z%, %player_world%, %player_health%, %player_max_health%, %player_level%, %player_exp%, %player_food%, %player_gamemode%, %player_is_op%, %player_is_online%, %player_is_sneaking%, %player_is_flying%; доступны также PlaceholderAPI и поля ввода. Значения из поля ввода считайте пользовательским вводом и не вставляйте без проверки в чувствительные команды.

Console-префикс разрешается только после включения security.allow-console-commands и проверки security.console-command-allowlist из config.yml. Для сервера без ограничений allowlist по умолчанию пуст, но опасно включать console-команды для недоверенной конфигурации. Это защита запуска команд из YAML меню.

Переход, закрытие и обновление меню

next-menu:
  enabled: true
  menu: profile

stop-menu:
  enabled: true
  teleport:
    enabled: true
    back-original: true
  command:
    enabled: true
    list:
      - "[message] <gray>Сессия закрыта"

next-menu переводит в другое существующее меню и имеет приоритет над закрытием. Если нужен переход, обычно задают только next-menu, а stop-menu.enabled оставляют false. stop-menu.teleport.enabled закрывает меню и телепортирует: back-original: true возвращает сохранённую позицию входа; иначе используются world (мир меню по умолчанию), x: 0, y: 64, z: 0. Направление после возврата берётся из exit-camera.yaw/pitch основного config.yml (по умолчанию нули). stop-menu.command запускается после успешного закрытия и, при телепортации, после перехода.

refresh-menu обновляет текущее отображение после клика, если меню не закрывается и не переключается. Для секции refresh-menu: { enabled: true } значение enabled по умолчанию true; задержка delay/delay-ticks по умолчанию равна command-delay + 1 тиков, когда command-delay задан положительным числом, иначе одному тику. В старой краткой форме refresh-menu: true задержка не задаётся. Обновление полезно, если действие изменяет permissions или placeholders и это меняет visible-if.

Cooldown кнопки

cooldown:
  enabled: true
  key: shared_profile_cooldown
  seconds: 5
  denied:
    actionbar: "<red>Подождите {cooldown.left} сек."

Cooldown включён, если секция задана; без неё блокировки нет. Допустимые формы длительности: ticks, seconds, time или duration; time/duration понимают числа в секундах и суффиксы ms, t/tick/ticks, s. Например, time: 5s. Без key создаётся отдельный ключ для меню и элемента. Общий одинаковый key позволяет делить перезарядку между кнопками. В denied задаются message, actionbar, commands; {cooldown.left}/%cooldown_left% показывают секунды вверх до целого, left_ticks — тики.

11. Поле ввода из чата

Клик по input-field выбирает имя поля. Следующее сообщение игрока в чат перехватывается и сохраняется UIcore; оно не публикуется в общий чат. После ввода отображение обновляется. Значение можно показать как {input.nickname}, {menu.input.nickname}, %input_nickname% или %uicore_input_nickname%. Значение ограничено 4096 символами. Команда /uicore input <field> <value> также задаёт значение. Команда /uicore set_input_field <field> вручную выбирает поле для ввода.

nickname:
  type: input-field
  name: "<gray>Имя: <white>{input.nickname}"
  field: nickname
  x: 0
  y: 0.2
  z: 3.5
  input-field:
    prompt: "<yellow>Введите имя в чат"

Поля с именем password, confirm_password или содержащим слово password маскируются звёздочками при выводе через обычный display/PlaceholderAPI. Не отправляйте секретные поля командами и сторонним API без обдуманной обработки. При закрытии меню кэш ввода очищается. /uicore input удобен для администраторского заполнения и не предназначен как безопасный парсер произвольного пользовательского ввода.

12. Текстовая шкала bar-text

bar-text строит ряд из заполненного/пустого символа. Значения обрабатывают плейсхолдеры игрока; value ограничивается диапазоном от нуля до max. По умолчанию value: "0", max: "100", segments: 10, символы заполнения и пустоты — |.

health:
  type: bar-text
  value: "%player_health%"
  max: "%player_max_health%"
  segments: 10
  filled: "<green>|"
  empty: "<dark_gray>|"
  prefix: "<red>Здоровье "
  suffix: " <gray>{value}/{max} — {percent}%"
  x: 0
  y: -0.4
  z: 3.5

segments ограничен 1–256. В суффиксе/префиксе можно использовать {value}, {max}, {percent}, {filled}, {empty}. Результат — текстовый display, не интерактивный HUD. segments задаёт число символов, а их ширина зависит от шрифта клиента.

13. Анимации

Появление элемента

entrance-animation:
  enabled: true
  from: left
  delay: 10
  duration: 12
  distance: 1.2
  easing: ease-out-cubic

Направления: top, bottom, left, right, front, back. Задержка и длительность указаны в тиках. По умолчанию при включённой секции анимация включена, from: top, delay: 0, duration: 10 (ограничивается максимумом 59), distance: 1. Поддерживаемые easing: linear, ease-in-cubic, ease-out-cubic, ease-in-out-cubic, ease-out-back. Для очередности элементов задавайте разный delay.

Непрерывная анимация

animation задаёт непрерывную анимацию текстового элемента. Можно указать сокращённую форму animation: "bounce" или блок со значениями:

animation:
  enabled: true
  type: move
  axis: y
  speed: 1.2
  amplitude: 0.12

Типы: move, fade, rotate, scale, bounce. Блок по умолчанию включён, speed: 1.0, amplitude: 0.25, axis: y. move перемещается по вертикали; axis: x перемещает влево/вправо. Скорость — коэффициент времени в синусоидальном движении; для вращения задаёт радианы в секунду. Амплитуда у move/bounce задаётся в блоках, у scale — множитель относительно исходного размера. floating-animation — старый совместимый блок (up-down/float-y, left-right/float-x, rotate, scale/pulse, fade, bounce); он выключен по умолчанию. Если заданы обе секции, animation имеет приоритет.

Эти непрерывные анимации применяются к текстовым TextDisplay. Для ItemDisplay используйте rotate: true и rotate-speed (градусы за тик), см. раздел о предметах. Не путайте скорость вращения ItemDisplay с параметром speed текстовой анимации.

14. Формулы координат и плавность

x, y, z принимают числа или формулы. Формулы повторно вычисляются, пока меню открыто. В t — время в секундах от начала активной сессии, ticks — тики, pi и e — математические константы. Операторы: +, -, *, /, %, скобки, унарные +/-.

Функции:

Функция Аргументы Пример
sin, cos, abs 1 sin(t * 2)
min, max 2 max(%player_level%, 1)
clamp, normalize, lerp 3 clamp(t, 0, 3)
map 5 map(%player_level%, 1, 100, -1, 1)

Формула принимает %placeholderapi_placeholder% и {state.key} как внешние значения. Они должны разрешаться в конечное число; иначе формула для этой оси оставит последнее значение/резервную координату и запишет предупреждение.

moving_label:
  name: "<aqua>Двигаюсь"
  x: "0.9 * sin(t * 1.4)"
  y: 0.2
  z: 3.5
  position-update:
    interval: 1
    smoothing: 0.18
    fallback: { x: 0 }
    clamp:
      x: [-1.0, 1.0]
Настройка position-update Значение по умолчанию Назначение
interval или interval-ticks 1 тик Период обновления, ограничен диапазоном 1–1200 тиков
smoothing 1.0 Множитель шага к цели, ограничен 0.01–1; 1 перемещает сразу
fallback.x/y/z статическое число из этой координаты Начальная/резервная координата, если выражение неверно или значение нечисловое
clamp.x/y/z без границ Пара [min, max], ограничивающая итоговую позицию

Счётчик времени формулы начинается заново при открытии меню. Сглаживание уменьшает резкость и скорость перемещения. Для слотов формулы разрешены в координатах позиции; настройки position-update слота заменяют соответствующие параметры шаблона.

15. Шаблоны, слоты и карусель предметов

Шаблон — обычное полное определение элемента в корне templates. Он появится только когда его выберет слот. Положение и необязательный хитбокс задаются в слоте; остальное берётся из шаблона. content — исходный template ID/строка-переменная, fallback — резервный template ID.

showcase:
  camera-position: { type: player, distance: 1.5 }
  templates:
    bronze:
      type: item
      material: IRON_SWORD
      scale: 0.7
      transform: gui
      hitbox: { width: 0.9, height: 0.9, depth: 0.4 }
    silver:
      type: item
      material: DIAMOND_SWORD
      scale: 0.7
      transform: gui
  slots:
    reward:
      x: 0
      y: 0.2
      z: 3.5
      content: bronze
      fallback: bronze

content может содержать %PlaceholderAPI% или {state.key} для выбора шаблона. Если шаблон не найден, используется корректный fallback, иначе слот пуст. Явное назначение слота для игрока имеет приоритет над глобальным назначением и конфигурационным content; явное пустое назначение очищает слот. Назначения разных игроков не смешиваются. hitbox и визуальные параметры берутся из шаблона; координаты слота задают позицию.

/uicore slot set <player> <menu> <slot> <template>
/uicore slot clear <player> <menu> <slot>
/uicore slot reset <player> <menu> <slot>
/uicore slot transition <player> <menu> <slot> <template> <direction> <ticks> [distance] [easing]
/uicore slot refresh <player> <menu>
/uicore slot set-global <menu> <slot> <template>
/uicore slot clear-global <menu> <slot>
/uicore slot reset-global <menu> <slot>

clear временно назначает пустой слот; reset снимает переопределение и возвращает конфигурационный выбор. Global-варианты относятся ко всем игрокам. Все команды требуют uicore.slot. slot transition анимирует уход текущего предмета; направление — поддерживаемая сторона (top, bottom, left, right, front, back), длительность — тики. Сейчас новый предмет появляется в целевой позиции без согласованной входящей анимации, даже если на шаблоне указан entrance-animation. Учитывайте это при дизайне карусели. Внешний плагин может управлять назначениями через UIcore Java API; случайный выбор и игровые награды должны определяться его собственной логикой.

Подробности Java API разработчика плагинов — в файлах проекта docs/API_USAGE.md и docs/RUNTIME_CONTRACTS.md.

16. Схематики как клиентское оформление

Положите до четырёх Sponge .schem версии 2 или 3 в plugins/UIcore/schematics/; в меню можно перечислить файлы:

schematics:
  - file: frame.schem
    anchor: camera
    x: -2
    y: -1
    z: 4
  - file: floor.schem
    anchor: world
    x: 100
    y: 65
    z: 100

Имя файла — одно имя с расширением .schem, без путей и подпапок; допустимы латинские буквы, цифры, _, -, .. anchor: camera берёт позицию камеры и добавляет целочисленные координаты по осям мира; это не поворот по yaw камеры. anchor: world трактует их как абсолютные block-координаты в мире камеры меню. В обоих случаях применяется внутренний Offset файла. После изменения файла выполните /uicore reload.

Схемы изменяют клиентское изображение только зрителя меню; настоящие блоки мира не меняются. При закрытии/смене меню отправляются актуальные блоки мира для восстановления. Показ идёт пакетами до 512 блоков за тик, общий размер — до 65 536 блоков; файл — до 8 MiB сжатых и 16 MiB распакованных данных. Содержимое block entities (например, табличка), сущности, биомы и состояния, которых нет на сервере, не воспроизводятся как содержимое схемы. При неподдерживаемом блоке проверяйте лог сервера.

17. WASD, дополнительные NPC и отдельные display-файлы

Навигация WASD

WASD-модуль подключается в plugins/UIcore/wasd_config.yml. В меню его можно выключить через wasd-enabled: false (по умолчанию true). Модуль выбирает ближайшие текстовые элементы по направлению; W/S — вверх/вниз, A/D — в стороны, jump активирует выбранный пункт. Это отдельная навигация и не двигает курсор мыши. menu-settings в конфиге ограничивает меню allowlist/режимом списков. Звук выбора, порог направления и cooldown находятся в wasd_config.yml.

При установленном PlaceholderAPI доступны expansion %uicorewasd_wasd_menu%, %uicorewasd_wasd_enabled%, %uicorewasd_wasd_index%, %uicorewasd_wasd_x%, %uicorewasd_wasd_y%, %uicorewasd_wasd_z%, %uicorewasd_wasd_xyz%, %uicorewasd_wasd_location%; имя меню также можно поставить перед суффиксом _x, _y, _z, _xyz для координаты элемента этого меню.

Зеркальный NPC

NPC-зеркало настраивается общим npc_config.yml; конкретное меню может переопределить его в верхнем npc:. Интеграция требует FancyNpcs. Положение задаётся offset.x/y/z, поворот — yaw-offset и pitch, auto-rotate.enabled/speed включает оборот, sync.skin/equipment синхронизирует скин и надетые предметы, name-display.show/format задаёт подпись с %player%. enabled-menus + use-whitelist-mode управляют списком меню, если меню не переопределило npc.enabled. custom-model требует поддерживающую интеграцию FancyNpcsModel/провайдера модели; если её нет, оставьте выключенным. NPC — отдельный объект перед камерой; его настройки не меняют avatar ItemDisplay.

Отдельные предметы и текст

items.yml описывает предметы для /uicore items <id>: material, custom-model-data, scale (по умолчанию 0.3), offset.x/y/z (z по умолчанию 2), glow (true), rotate (false), rotate-speed (1). /uicore itemsstop убирает показ. Это отдельный показ предмета, не layout.

text.yml описывает именованные текстовые display-группы для /uicore text open <id> [player]. В каждом элементе menus перечисляет ID меню; content — строка или список, position.x/y/z, scale, tilt.x/y/z, alignment (center по умолчанию; допустимы left/right), animation.enabled/type/speed/amplitude/phase-offset/spacing, typewriter.enabled/speed/start-delay/cursor-char, duration в секундах (по умолчанию 30). Для короткой информации, которая должна появляться как часть меню, используйте обычный layout.

18. PlaceholderAPI и переменные UIcore

PlaceholderAPI доступен только при установленном PlaceholderAPI. Обычный UIcore expansion имеет имя %uicore_<параметр>%:

Плейсхолдер Значение
%uicore_current_menu% ID активного меню
%uicore_selected_option% Имя выбранного/наведённого элемента
%uicore_clicked_option% ID элемента
%uicore_hovered_option% ID элемента под курсором
%uicore_button_x%, %uicore_button_y%, %uicore_button_z% Координаты активного выбранного элемента
%uicore_menu_world% Мир активного меню
%uicore_display_item_id% ID показанного standalone-предмета
%uicore_input_<field>% Значение введённого поля; пароли маскируются
%uicore_is_attacking_or_breaking% Краткоживущее состояние metadata взмаха/ломания, не надёжный признак удерживания мыши

Без активного меню значения в основном пусты. {state.key} для условий/формул и для выбора контента слота — серверное состояние данных меню, которое может задавать API. {input.name} — поле ввода. states: — варианты текста/видимости конкретного элемента. Эти три механизма не взаимозаменяемы.

19. Общий config.yml и важные ограничения

Кроме настроек курсора, основной config.yml содержит:

Параметр Начальное значение Назначение
use-player-location false Игнорировать camera-position и брать позицию игрока
use-pumpkin-overlay false Надевать клиентский overlay при меню
camera-block-check.enabled/radius true / 1 Скрыть закрывающие камеру блоки только для зрителя
creature-spawn-limits.enabled/radius false / 10 Ограничивать спавн существ у камеры
exit-camera.yaw/pitch 0 / 0 Направление игрока при возврате
sound.name/volume/pitch music.menu / 1 / 1 Звук активной сцены; цикл включён с периодом 30 секунд
join-run.enabled/delay/menu false / 3 сек. / demo_main Открыть меню при входе
security.allow-console-commands false Разрешить console-префикс из доверенных меню после allowlist
security.allow-op-commands-for-existing-ops false Разрешить [op] только уже OP-игроку

Скрытие блоков камеры не меняет настоящий мир. На Folia задачи меню привязаны к региону игрока/сущности; расстояние переносимых элементов и межрегиональные схемы/NPC не превращают меню в глобальный viewer entity manager. Держите интерактивные элементы рядом с камерой игрока и проверяйте целевую Folia-сборку.

Конфиг проверяет корректность материалов и положительность размеров scale, text-size, hitbox и hover-enlarge.scale; слишком большие или нечисловые значения следует исправить. Уникальные ID элементов, слотов, шаблонов и вариантов состояний помогают избежать путаницы. Используйте кавычки для MiniMessage/формул и YAML-слов on, off, чисел, которые нужно трактовать как строки.

20. Проверка готового меню

Перед публикацией убедитесь, что:

  • у каждого меню есть camera-position, а каждый next-menu.menu указывает на существующий ID;
  • все элементы попадают в диапазон курсора, получают осмысленный хитбокс и не перекрываются соседними хитбоксами;
  • предмет выглядит так, как задумано, при выбранном transform, billboard, tilt, масштабе и активном ресурспаке;
  • у аватара выбран правильный player, разумный face-only, нулевой начальный tilt, подходящий billboard и отдельная кликабельная область;
  • visible-if, permission элемента и click-requirements проверяют разные нужные вещи и не создают неожиданно невидимые/доступные кнопки;
  • все states и цели set-state/set-states существуют и кликабельные кнопки имеют hitbox;
  • переход проверен отдельно от закрытия и телепорта; console-команды работают только при сознательно настроенном allowlist;
  • схемы существуют, размеры разумны, файлы находятся только в schematics/, а макет проверен при закрытии меню;
  • после правок выполнен /uicore reload и прочитан журнал сервера.

Быстрые диагностические команды: /uicore run <menu>, /uicore stop, /uicore reload, /uicore slot ..., /uicore items <id>, /uicore text open <id>. Для Java-интеграций смотрите docs/API_USAGE.md; UIcore не включает специальную интеграцию Skript.

UIcore основан на CustomScreenMenu. Уведомления о сторонних компонентах входят в комплект выпуска.
