# Группы, перетаскивание и зум в UIcore 1.1.0

Добавлены `parent`, невидимые группы `type: group`, перетаскивание, ползунки, зоны приёма и `/uicore debug`. Полный синтаксис: [English](INTERACTIONS_1_1.md). Пример: `/uicore run demo_drag`.

`parent: window` делает координаты элемента относительными к родителю. Перемещаются потомки и их хитбоксы. Скрытый или отсутствующий родитель скрывает потомков. Циклы и неверные ссылки отклоняются при загрузке. Наследуется положение, включая координатные формулы, но не масштаб, вращение и визуальные эффекты появления/плавания.

У drag есть два явно различающихся режима:

- `drag-input: click` — клик захватывает элемент, повторный клик кладёт. Это режим по умолчанию, он сохраняет spectator-камеру.
- `drag-input: block-digging` — экспериментальное перетаскивание удержанием ЛКМ. Перед камерой появляется невидимый неразрушаемый блок. Попытка его сломать начинает перетаскивание, отмена завершает. Настоящий мир не меняется. Нужна пустая основная рука. Начиная с 26.1 клиент получает режим Creative с отключённым мгновенным ломанием, чтобы скрыть полоску опыта. Более старые клиенты используют Survival. В этом режиме отключены движение камеры у края и катсцены. Если блок пропадёт из прицела, перетаскивание может завершиться при зажатой кнопке.

В режиме `block-digging` Minecraft рисует прицел от первого лица даже при скрытой полоске опыта. При ручном тестировании нажмите **F1**, чтобы скрыть ванильный HUD, и нажмите **F1** снова после выхода из меню. Режим `drag-input: click` с камерой наблюдателя скрывает прицел автоматически.

`drag.target` позволяет заголовку перемещать родительскую группу. `drag.axis` ограничивает ось, `drag.bounds.x/y` задают границы в координатах родителя перемещаемого элемента. Глубина сохраняется. Положение персональное, действует до закрытия меню и не записывается в YAML. Формула положения захваченного элемента уступает его новому положению до конца посещения.

`slider: {state: volume, min: 0, max: 100, step: 5}` вместе с одной осью и её границами записывает значение в `{state.volume}`. При отмене возвращается предыдущее значение.

### Зум колёсиком

Зум включается на уровне меню. Без `group` масштабируются все элементы, привязанные к камере. С `group: board` масштабируются потомки группы `board`, а остальные элементы остаются на месте.

```yaml
zoom:
  enabled: true
  group: board       # необязательно
  min: 0.6
  max: 1.8
  step: 0.2
  sensitivity: 1
  smoothing: 0.45   # 1 применяет шаг сразу
  pivot: {x: 0, y: 0}
```

Точка масштабирования задаётся относительно группы или начала координат меню. Положение, размер текста и предметов, а также хитбоксы масштабируются вместе. Глубина сохраняется. По умолчанию диапазон `0.5–2.0`, допустимые пределы от `0.25` до `4.0` и должны включать `1.0`. Масштаб сбрасывается при смене или закрытии меню. Пока элемент захвачен, зум на паузе, чтобы координаты перетаскивания оставались стабильными.

Зум сохраняет камеру наблюдателя. Он не открывает ванильный экран и не требует мод или ресурс-пак. Ванильный клиент получает Adventure в данных игрока и отправляет смену выбранного слота. UIcore использует шаги между соседними слотами, включая переход с края на край, при этом серверный слот не меняется. Прыжок на несоседний слот зум не меняет. Соседняя цифра и шаг колеса приходят одинаковым пакетом. При закрытии или смене меню клиенту возвращается серверный слот. Зум работает с `drag-input: click`.

Проверить можно через `/uicore run demo_zoom`. Покрути колесо, нажми на алмаз для захвата и нажми ещё раз, чтобы его положить.

`drag.drop-targets: [socket]` разрешает размещение только в перечисленных зонах. При отказе предмет возвращается назад. `drop-accepts: [gem]` ограничивает принимаемые ID. Пустой слот с таким списком или непустым `on-drop` сохраняет хитбокс.

### Действия после сброса

Пример для принимающего слота:

```yaml
drop-accepts: [gem]
on-drop:
  - '[state] socket_filled true'
  - '[actionbar] <green>Кристалл установлен'
  # Можно вызвать зарегистрированное действие Java-расширения:
  # - '[action] puzzles:place_gem'
```

`on-drop` можно задать на ручке перетаскивания и на принимающем элементе или слоте. UIcore сохраняет итоговую позицию и значение ползунка, вызывает `MenuDropEvent`, затем выполняет действия ручки и принимающей стороны в этом порядке. При свободном сбросе действуют только команды ручки. При отказе или отмене действия пропускаются. Если обработчик закрывает или переключает меню, оставшиеся действия для прежнего меню пропускаются.

Поддерживаются обычные команды меню, `[state]`, `[element-state]` и `[action]`. Java-обработчик получает ID владельца действия через `context.elementId()` и аргументы `drag-handle`, `drag-target` и, при наличии зоны, `drop-target`. Отложенное действие сохраняет этот контекст и требует того же сеанса меню. Успешный сброс запускает заданные cooldown ручки и зоны. Ошибка действия не откатывает перенос.

`pointer-events: false` исключает декорацию из наведения и кликов. `interaction-priority` задаёт порядок выбора перекрывающихся элементов. `/uicore debug` показывает контуры хитбоксов и связи родителей частицами, ID выбранного элемента — в action bar; право `uicore.debug` по умолчанию доступно OP.

API получает событие `MenuDragEvent` с фазами START/MOVE/DROP/CANCEL. START, MOVE и DROP можно отменить. За подтверждённый перенос отвечает отдельное событие `MenuDropEvent` с итоговыми координатами. Через него расширение может выполнить игровое действие, например перенести шаблон слота. Оба события работают на планировщике игрока. Закрытие, переключение меню, скрытие или замена элемента отменяют текущий захват. Перетаскивание элементов с мировой привязкой пока не поддерживается.

Локальная сборка находится в `uicore-plugin/target/UIcore-1.1.0.jar`. [Скачать релиз](https://github.com/kekaop/UIcore/releases/tag/v1.1.0) · [Проверки взаимодействия](interaction-verification/README.md).
