# Расширения UIcore

Сторонний плагин может добавить действие, источник данных, условие и составной компонент. Администратор использует их в обычном YAML-меню. Регистрации принадлежат Bukkit-плагину и удаляются, когда он отключается. [English version](EXTENSION_API_EN.md).

Vault и LuckPerms уже поддерживаются внутри UIcore. Их готовые идентификаторы и примеры находятся в [руководстве по встроенным интеграциям](BUILTIN_INTEGRATIONS_RU.md).

В [`uicore-example-extension`](../uicore-example-extension/) находится собираемый пример. Его JAR устанавливают рядом с UIcore. Пример меню [`example_extension.yml`](../uicore-example-extension/example_extension.yml) копируют в папку `plugins/UIcore/menu/`.

## Зарегистрируйте обработчики

Получите `UIcoreApi` через `UIcoreProvider.get()` после включения UIcore. При регистрации передавайте `this` как плагин-владелец:

```java
UIcoreApi api = UIcoreProvider.get();

api.actions().register(this, "quests:accept", context -> {
    String quest = context.argument("quest");
    questService.accept(context.player(), quest);
});

api.data().register(this, "economy:balance", 20, context ->
    economy.getBalance(context.player())
);

api.conditions().register(this, "quests:completed", context ->
    quests.hasCompleted(context.player(), context.argument("id"))
);

api.components().register(this, "quests:quest-card", context -> List.of(
    MenuElementSpec.builder("title")
        .text("<gold>" + context.parameter("title"))
        .position(0, 0.3, 0).build(),
    MenuElementSpec.builder("accept")
        .text("<green>Принять")
        .position(0, 0, 0)
        .action("quests:accept", Map.of("quest", context.parameter("quest")))
        .build()
));
```

Идентификаторы имеют вид `namespace:name` и состоят из строчных латинских букв, цифр, `_`, `-` и `.`. Повторная регистрация идентификатора в том же типе расширения выдаёт ошибку. Возвращённый `ExtensionRegistration` можно закрыть вручную; при отключении плагина UIcore очищает его регистрации автоматически.

Обработчики вызываются в контексте региона игрока на Paper/Folia. Не выполняйте в них долгие операции. Если результат вычисляется асинхронно, применяйте его через планировщик игрока и проверяйте, что меню всё ещё открыто. Не вызывайте Bukkit API из произвольного асинхронного callback.

## Используйте расширения в YAML

```yaml
quest_menu:
  camera-position:
    type: player
    distance: 1.5
  layout:
    balance:
      name: '<gold>Баланс: {economy:balance}'
      x: 0
      y: 0.5
      z: 3.5
    accept_button:
      name: '<green>Принять квест'
      x: 0
      y: 0
      z: 3.5
      action:
        type: quests:accept
        quest: daily_1
      visible-if:
        custom:
          type: quests:completed
          id: tutorial
```

`action` срабатывает при клике после обычных проверок видимости, разрешений и задержки. Аргументы действия и условия пока допускают только строку, число или логическое значение. Если действие вызывает `context.cancel()`, дальнейшая обработка этого клика прекращается.

`{economy:balance}` подставляется при рендеринге текста как обычный текст, поэтому значение не интерпретируется как MiniMessage-разметка. Для источника данных можно задать минимальный интервал обновления в тиках; без явного параметра он равен одному тику. Вызов `api.refresh(player)` сбрасывает кэш данных для игрока и обновляет открытое меню.

Числовой источник данных можно использовать в динамических координатах, например `x: "{economy:balance} / 100"`, а также как точное значение `bar.value`, `bar.max` и `custom-model-data`. Строковый источник можно указать вместо `material`, логический — вместо `glow`. Для свойств предмета используется ссылка целиком, например `material: '{items:current-material}'`.

Пользовательское условие работает внутри `visible-if`, в том числе с `all`, `any` и `not`. Отсутствующее условие или ошибка обработчика дают отрицательный результат, включая случай `not`; меню не становится видимым из-за сбоя проверки.

Неизвестный идентификатор и сбой обработчика записываются в журнал UIcore без значений аргументов. Одинаковые сообщения ограничены по частоте. Ошибка одного обработчика не останавливает остальные меню.

После включения зависимых плагинов UIcore проверяет ссылки на расширения в меню и шаблонах. Сообщение указывает ID меню и элемента, путь свойства, тип расширения и неизвестный ID. Проверка повторяется при перезагрузке конфигурации. Отсутствие расширения не мешает загрузить меню; действие или компонент станет доступным после регистрации владельца.

## Составные компоненты

Компонент создаёт обычные элементы UIcore для конкретного игрока. Параметры из YAML доступны через `ComponentContext.parameter`. Координаты компонента и его дочерних элементов задаются числами; дочерние координаты считаются относительно позиции компонента. ID дочернего элемента получает префикс ID компонента, например `profile/title`. Компонент может вернуть другой зарегистрированный компонент. Максимальная вложенность — четыре уровня, не более 64 дочерних элементов за один вызов, 256 вызовов фабрик и 256 элементов в одном раскрытии меню.

```yaml
profile:
  type: quests:quest-card
  title: Ежедневный квест
  quest: daily_1
  x: 0
  y: 0
  z: 3.5
```

Права и `visible-if` родительского элемента проверяются до вызова фабрики. После отключения расширения его элементы удаляются при обновлении открытого меню. Фабрика вызывается в контексте региона игрока; результат кэшируется в пределах одного тика. UIcore повторно использует дочерний `MenuLayout`, пока его описание не меняется, сохраняя состояние клика. Используйте `api.refresh(player)`, когда результат фабрики зависит от изменившегося состояния.

## Добавьте расширение из Java

Программно созданный элемент проходит через тот же `MenuLayout`, что и элемент из YAML:

```java
MenuElementSpec button = MenuElementSpec.builder("accept_button")
    .text("<green>Принять квест")
    .position(0, 0, 3.5)
    .action("quests:accept", Map.of("quest", "daily_1"))
    .visibleIfCustom("quests:completed", Map.of("id", "tutorial"))
    .build();

api.addElement("quest_menu", button);
```

Строковое состояние из API 1.1 сохраняется. Для типизированного доступа используйте `StateKey.integer`, `StateKey.decimal`, `StateKey.bool` или `StateKey.string`:

```java
StateKey<Integer> page = StateKey.integer("page", 1);
api.state(player, "quest_menu").set(page, 3);
int currentPage = api.state(player, "quest_menu").get(page);
```

Типизированный слой читает и пишет то же состояние, которое используют существующие YAML-условия. Если старое значение невозможно преобразовать, `get` возвращает значение по умолчанию.
Состояние разделено по игроку и ID меню, живёт в памяти в течение сеанса меню и очищается при завершении сеанса или выходе игрока. Оно не сохраняется между перезапусками сервера.

Для новых интеграций доступны группы методов `api.menus()`, `api.elements()`, `api.inputs()` и `api.slots()`. Они делегируют операции прежним методам `UIcoreApi`; старые вызовы остаются доступны.

Описание элемента внутри API хранится в неизменяемой `UiElementModel`. YAML-загрузка, Java API и фабрики компонентов приводят свойства к этой модели, после чего UIcore создаёт `MenuLayout` для существующего рендерера. `MenuElementSpec.model()` и `MenuElementEditor.model()` дают доступ к описанию без `YamlConfiguration`; старый `toConfiguration()` сохранён для совместимости.

Новые меню могут указать `schema-version: 2` внутри секции меню. Существующие меню без этого поля считаются версией 1 и продолжают загружаться. Сейчас обе версии читаются одинаково; неизвестная версия вызывает ошибку загрузки с ID меню. Для миграции старого меню достаточно оставить его как есть. Поля расширений можно использовать и без смены версии.

## Текущее покрытие ТЗ 2.0

Реализованы Action, Data Provider, Condition и композиционный Component API, владение регистрациями, группы методов меню, элементов, полей ввода и слотов, базовая диагностика, типизированное состояние, проверка версии схемы и независимое от YAML исходное описание элемента. Рендерер всё ещё использует существующий `MenuLayout`; привязка данных ко всем свойствам элементов пока не реализована. Сборка, тесты и запуск/остановка UIcore с примером на Paper 26.1.2 прошли. Клик, подстановка данных и отрисовка компонента с подключённым игроком, а также Folia требуют игровой проверки.
