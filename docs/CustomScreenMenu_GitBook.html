CustomScreenMenu Documentation

A GitBook-style single-file guide for server owners and plugin developers.

CustomScreenMenu creates fixed-camera world-space menus using TextDisplay, ItemDisplay, a cursor entity, PacketEvents input, commands, placeholders, hover effects, and optional NPC/WASD integrations.

Menu runtimeOpen fixed-camera menus with text, item previews, hover and click actions.
Config drivenMenus are YAML files under the plugin data folder.
Developer APIOpen, close, edit elements, and read chat input fields from other plugins.

CustomScreenMenu 文档

面向服主和插件开发者的 GitBook 风格单文件文档。

CustomScreenMenu 使用固定摄像机、TextDisplay、ItemDisplay、光标实体、PacketEvents 输入、命令、变量、悬停效果，以及可选的 NPC/WASD 集成来制作世界空间菜单。

菜单运行时打开带文本、物品预览、悬停和点击动作的固定摄像机菜单。
配置驱动菜单由插件数据目录中的 YAML 文件定义。
开发者 API其他插件可以打开、关闭、编辑元素并读取聊天输入字段。

Install

  1. Install Paper 26.1.2 or the server version supported by your build.
  2. Install required dependencies: PacketEvents and PlaceholderAPI if your menus use PlaceholderAPI variables.
  3. Place the jar in the server plugins folder.
  4. Restart the server, then edit generated files under plugins/CustomScreenMenu/.
Use a full restart after replacing the jar. /cmenu reload reloads YAML, but it does not replace Java classes.

安装

  1. 安装 Paper 26.1.2，或当前构建支持的服务端版本。
  2. 安装依赖：PacketEvents；如果菜单使用 PlaceholderAPI 变量，也需要安装 PlaceholderAPI。
  3. 将 jar 放入服务器 plugins 文件夹。
  4. 重启服务器，然后编辑 plugins/CustomScreenMenu/ 中生成的配置。
替换 jar 后请完整重启服务器。/cmenu reload 只会重载 YAML，不会替换 Java 类。

Commands

CommandPurpose
/cmenu run <menu>Open a menu.
/cmenu stopClose the current menu.
/cmenu reloadReload configuration and menu YAML files.
/cmenu input <field> <value>Set a menu input field directly.
/cmenu set_input_field <field>Focus a chat input field for the current player.
/cmenu toggle_password_visibilityShow or hide password-like input values in menu text.

命令

命令用途
/cmenu run <menu>打开菜单。
/cmenu stop关闭当前菜单。
/cmenu reload重载配置和菜单 YAML 文件。
/cmenu input <field> <value>直接设置菜单输入字段。
/cmenu set_input_field <field>让当前玩家聚焦一个聊天输入字段。
/cmenu toggle_password_visibility显示或隐藏类似密码的输入值。

Menu File

Menu files live in plugins/CustomScreenMenu/menu/*.yml. Each top-level key is a menu id.

菜单文件

菜单文件位于 plugins/CustomScreenMenu/menu/*.yml。每个顶级键都是一个菜单 ID。

demo_main:
  permission: cursormenu.menu.demo_main
  wasd-enabled: true
  camera-position:
    world: world
    x: 0.0
    y: 80.0
    z: 0.0
    yaw: 0.0
    pitch: 0.0
    distance: 1.5
  layout:
    title:
      name: "<gold><bold>Demo Menu</bold>"
      x: 0.0
      y: 0.55
      z: 3.5
      text-size: 0.55

Positioning, Hitboxes And Cursor

Each menu uses a fixed camera scene. camera-position defines where the camera entity is placed, which way it looks, and how far the cursor plane is from the camera. Layout elements are placed in the same scene: x moves left/right, y moves up/down, and z moves forward from the camera.

For the current test menus, use camera-position.distance: 1.5 and element z: 3.5. Keep most clickable elements on the same z plane unless you intentionally build a layered depth effect.

定位、点击框和光标

每个菜单都是固定摄像机场景。camera-position 定义摄像机实体的位置、朝向，以及光标平面距离摄像机多远。布局元素放在同一个场景里：x 控制左右，y 控制上下，z 控制摄像机前方的深度。

当前测试菜单建议使用 camera-position.distance: 1.5 和元素 z: 3.5。除非你有意制作前后层次效果，否则大多数可点击元素应保持在同一个 z 平面。

button_start:
  name: "<green>Start"
  x: 0.0
  y: 0.1
  z: 3.5
  text-size: 0.45
  command:
    - "[message] <green>Clicked Start"

Clickable text is checked against a TextDisplay hitbox. For short labels or item elements, set a custom hitbox so the cursor target matches the visible button area.

可点击文本会通过 TextDisplay 点击框检测。对于短文本或物品元素，请设置自定义 hitbox，让光标目标和可见按钮区域一致。

button_start:
  name: "<green>Start"
  x: 0.0
  y: 0.1
  z: 3.5
  hitbox:
    width: 0.9
    height: 0.28
    depth: 0.25

# config.yml
cursor-item:
  material: ARROW
  custom-model-data: 0
  scale: 0.5
  sensitivity: 1.0
  smoothing: 1.0
  max-x: 2
  max-y: 3
  x: 0.0
  y: 0.0
  z-offset: 0.0
  movement-range:
    enabled: false
    x:
      min: -2.0
      max: 2.0
    y:
      min: -3.0
      max: 3.0
If clicks feel offset from the visual cursor, tune element z, camera-position.distance, and custom hitbox values together.
如果点击位置和可见光标有偏差，请一起调整元素 z、camera-position.distance 和自定义 hitbox。

Styles And Hover

Elements can use base style, hover style, permission style, pressed style, hover cursor, and hover tooltip.

样式与悬停

元素支持基础样式、悬停样式、权限样式、按下样式、悬停光标和悬停提示。

settings_button:
  name: "<gray>Settings"
  x: 0.0
  y: -0.1
  z: 3.5
  style:
    color: "#cbd5e1"
  hover-style:
    color: "#ffffff"
    underlined: true
    transition:
      type: smooth
      duration: 6
  pressed-style:
    text: "<green>Opening..."
    color: "#62e67a"
    duration: 5
  permission-style:
    denied:
      color: "#777777"
      strikethrough: true
  permission-denied:
    message: "<red>No permission."
    commands:
      - "[actionbar] <red>Access denied"
  hover-tooltip:
    type: actionbar
    text: "<yellow>Open settings"
  hover-cursor:
    enabled: true
    material: AMETHYST_SHARD
    scale: 1.2

Input Fields

Any menu can use chat-backed input fields. Click the field, type in chat, and the value is stored for the current player. The chat message is cancelled and the menu refreshes.

输入字段

任何菜单都可以使用基于聊天的输入字段。点击字段后在聊天中输入，值会保存到当前玩家。聊天消息会被取消，菜单会刷新。

nickname_field:
  type: input-field
  name: "<gray>Nickname: <white>{input.nickname}"
  field: nickname
  x: 0.0
  y: 0.2
  z: 3.5
  input-field:
    prompt: "<yellow>Type nickname in chat."

save_nickname:
  name: "<green>Save"
  x: 0.0
  y: -0.1
  z: 3.5
  command:
    - "[player] say My nickname is {input.nickname}"

Supported placeholders: {input.name}, {menu.input.name}, %input_name%, and %cursormenu_input_name%.

支持的变量：{input.name}、{menu.input.name}、%input_name%、%cursormenu_input_name%。

Menu Commands

Commands are executed when an element is clicked. MiniMessage is supported for chat messages and action bars through the built-in message helpers.

菜单命令

点击元素时会执行命令。通过内置消息工具发送聊天消息和 ActionBar 时支持 MiniMessage。

command:
  - "[message] <green>Saved!"
  - "[actionbar] <yellow>Current value: {input.nickname}"
  - "[player] say hello"
  - "[console] lp user %player_name% permission set example.permission true"
  - "[link]https://example.com|<aqua>Open website"
Avoid [op] in production menus unless the server owner explicitly accepts the risk.
生产环境中请尽量避免使用 [op]，除非服主明确接受风险。

Items And Text

Text menus can include item elements, and item menus can include normal text elements. Item elements use ItemDisplay plus a hidden TextDisplay hitbox for cursor click detection.

物品与文本

文本菜单可以包含物品元素，物品菜单也可以包含普通文本元素。物品元素使用 ItemDisplay，并用隐藏的 TextDisplay hitbox 做光标点击检测。

reward_item:
  type: item
  material: DIAMOND
  x: 0.0
  y: 0.25
  z: 3.5
  scale: 0.55
  rotate: true
  rotate-speed: 2.0
  hitbox:
    width: 0.8
    height: 0.8
  command:
    - "[message] <aqua>Diamond selected"

WASD Navigation And NPC Mirror

WASD navigation is an optional input mode for menus. It tracks a selected menu element, lets the player move selection with W/A/S/D, and executes the selected element with Space. It is useful for controller-like navigation or when cursor aiming is not comfortable.

NPC mirror is a visual companion feature. When enabled, the plugin asks FancyNpcs to create a player-like mirror near the menu camera, with optional skin/equipment sync. It does not replace the normal menu renderer.

WASD 与 NPC

WASD 导航和 NPC 镜像是可选高级系统。只在需要的菜单中开启，并在功能需要时安装对应可选依赖。

demo_main:
  wasd-enabled: true
  # Element positions are also used by WASD to decide the next selection.

# wasd_config.yml
enabled: true
debug-mode: false
navigation:
  horizontal-threshold: 0.5
  dot-product-threshold: 0.5
  selection-cooldown: 500
sound:
  enabled: true
  selection-sound: "minecraft:entity.experience_orb.pickup"
menu-settings:
  enable-for-all-menus: false
  use-whitelist-mode: true
  enabled-menus:
    - demo_main
    - demo_text_item

The NPC mirror module requires FancyNpcs. SkinsRestorer is optional and is only needed when skin sync is enabled.

NPC 镜像模块需要 FancyNpcs。SkinsRestorer 是可选依赖，只有启用皮肤同步时才需要。

# npc_config.yml
enabled: true
debug-mode: false
offset:
  x: 2.0
  y: 0.0
  z: -4.0
default-yaw: 180.0
default-pitch: 0.0
sync:
  equipment: true
  skin: true
menu-settings:
  enable-for-all-menus: false
  use-whitelist-mode: true
  enabled-menus:
    - demo_main

Useful WASD placeholders: %cmp_wasd_menu%, %cmp_wasd_enabled%, %cmp_wasd_index%, %cmp_wasd_x%, %cmp_wasd_y%, and %cmp_wasd_z%.

WASD 状态常用变量：%cmp_wasd_menu%、%cmp_wasd_enabled%、%cmp_wasd_index%、%cmp_wasd_x%、%cmp_wasd_y% 和 %cmp_wasd_z%。

Conditions

visible-if hides an element before rendering. Hidden elements do not receive hover or click. Conditions can use permissions, placeholders, local menu state, and all/any/not groups.

条件

visible-if 会在渲染前隐藏元素。隐藏元素不会触发悬停或点击。条件可以使用权限、PlaceholderAPI 变量、本地菜单状态，以及 all/any/not 组合。

world_only:
  name: "<green>Only in world"
  x: 0.0
  y: 0.2
  z: 3.5
  visible-if:
    placeholder: "%player_world%"
    equals: world

page_two:
  name: "<yellow>Page 2"
  x: 0.0
  y: 0.0
  z: 3.5
  visible-if:
    state.page: 2

admin_page_two:
  name: "<aqua>Admin Page 2"
  visible-if:
    all:
      - permission: "example.admin"
      - state:
          page: 2

Animation

TextDisplay elements support a small animation block. It is meant for lightweight UI feedback, not complex timelines.

动画

TextDisplay 元素支持轻量级 animation 配置。它适合菜单反馈，不是完整时间轴动画系统。

animated_title:
  name: "<gold>Animated"
  x: 0.0
  y: 0.5
  z: 3.5
  animation:
    type: bounce
    speed: 1.2
    amplitude: 0.12

fading_hint:
  name: "<gray>Click a button"
  animation:
    type: fade
    speed: 0.8
    amplitude: 0.25
Supported types: fade, move, rotate, scale, bounce. For move, use axis: x or axis: y.
支持类型：fade、move、rotate、scale、bounce。move 可设置 axis: x 或 axis: y。

Runtime API

Other plugins can get the API through Bukkit Services or through the plugin instance. The public API is intended for opening menus, closing menus, mutating loaded menu elements, refreshing viewers, and working with menu input fields.

运行时 API

其他插件可以通过 Bukkit Services 或插件实例获取 API。

Mutation Scope

Calls without Player are global and mutate the loaded in-memory menu for every viewer. Calls with Player create a player-only overlay and refresh only that player's active menu.

修改范围

不带 Player 的调用是全局修改，会影响所有查看该菜单的玩家。带 Player 的调用会创建仅属于该玩家的覆盖层，并只刷新该玩家当前打开的菜单。

// Global: visible to everyone using demo_main.
api.addElement("demo_main", element);

// Player-scoped: visible only to this player.
api.addElement(player, "demo_main", element);
CustomScreenMenuApi api = CustomScreenMenuProvider.get();
api.openMenu(player, "demo_main");
api.editElement("demo_main", "title", edit -> edit.text("<green>Updated"));
api.focusInputField(player, "nickname");
api.setInput(player, "nickname", "Orven");
String nickname = api.getInput(player, "nickname").orElse("");
api.refresh(player);
api.closeMenu(player);

Common API Calls

常用 API 调用

// Open / close
api.openMenu(player, "demo_main");
api.closeMenu(player);
api.closeMenu(player, false); // do not teleport back

// Inspect loaded menus
boolean open = api.isMenuOpen(player);
Optional<String> current = api.getOpenMenu(player);
Set<String> menuIds = api.getMenuIds();
List<String> elementIds = api.getElementIds("demo_main");

// Add a runtime element
api.addElement("demo_main",
    MenuElementSpec.builder("api_button")
        .text("<green>API Button")
        .position(0.0, -0.45, 3.5)
        .textSize(0.45)
        .commands(List.of("[message] <aqua>Clicked from API"))
        .hoverEnlarge(true, 1.2)
        .build());

// Edit an existing element
api.editElement("demo_main", "api_button", edit -> edit
    .text("<yellow>Updated")
    .set("pressed-style.text", "<green>Pressed")
    .set("pressed-style.duration", 5));

// Input fields
api.focusInputField(player, "nickname");
api.setInput(player, "nickname", "Orven");
String value = api.getInput(player, "nickname").orElse("");
api.clearInput(player, "nickname");

// Player-scoped menu state
api.setState(player, "demo_main", "page", "2");
String page = api.getState(player, "demo_main", "page").orElse("1");
api.clearState(player, "demo_main", "page");

// Redraw viewers after external state changes
api.refresh(player);
api.refreshMenu("demo_main");

Events

Other plugins can listen for lifecycle, hover, click, and chat input events.

事件

其他插件可以监听菜单生命周期、悬停、点击和聊天输入事件。

@EventHandler
public void onMenuClick(MenuClickEvent event) {
    if ("danger_button".equals(event.getElementId())) {
        event.setCancelled(true);
    }
}

@EventHandler
public void onMenuInput(MenuInputEvent event) {
    event.setValue(event.getValue().trim());
}

WASD And NPC Helper Hooks

These module calls are lower-level integration points. Most plugins should use CustomScreenMenuApi first, and only touch these hooks when integrating custom navigation or mirror behavior.

WASD 与 NPC 辅助钩子

这些模块调用属于较底层的集成点。大多数插件应优先使用 CustomScreenMenuApi，只有在接入自定义导航或镜像行为时才需要直接使用这些钩子。

// WASD state helpers
if (WASDModule.isModuleEnabled() && WASDModule.isMenuEnabled("demo_main")) {
    String selectedMenu = WASDModule.getPlayerCurrentMenu(player);
    Location selectedLocation = WASDModule.getPlayerCurrentLocation(player);
}

// NPC mirror lifecycle hooks, normally called by the menu runtime
if (NPCModule.isModuleEnabled()) {
    NPCModule.onMenuOpen(player, cameraLocation, yaw, pitch, "demo_main");
    NPCModule.onMenuSwitch(player, newCameraLocation, newYaw, newPitch);
    NPCModule.onMenuClose(player);
}

Runtime mutations are in-memory only. /cmenu reload reloads YAML files and discards runtime changes.

运行时修改只保存在内存中。/cmenu reload 会重新读取 YAML 文件，并丢弃运行时修改。

Notes

  • Use camera-position.distance: 1.5 and element z: 3.5 for the current test layout unless you intentionally tune the camera.
  • Use a restart after changing jars.
  • Use /cmenu reload after editing YAML files.
  • Input values are per player and are cleared when the player session is cleaned up.
  • Password-like field names are masked in menu text, but raw values are used in command placeholders.

注意事项

  • 当前测试布局建议使用 camera-position.distance: 1.5 和元素 z: 3.5，除非你需要主动调整摄像机。
  • 更换 jar 后请重启服务器。
  • 编辑 YAML 文件后使用 /cmenu reload。
  • 输入值按玩家保存，并在玩家会话清理时删除。
  • 类似密码的字段在菜单文本中会被隐藏，但命令变量使用原始值。
