# Движение камеры меню с помощью катсцен

> **Язык:** [English](CUTSCENES.md) | Русский

Катсцена управляет камерой открытого меню UIcore. У каждого игрока отдельный сеанс, курсор, прогресс и выбор. Координаты точек задают **положение глаз камеры**, в блоках, в одном мире. Смещения игрока и сущностей камеры рассчитывает плагин. Катсцены не изменяют блоки мира и не требуют клиентского мода.

Для нажатия на элементы используйте **левую кнопку мыши**. Меню использует отдельную клиентскую display-камеру и отображение режима наблюдателя, чтобы скрыть руку и перекрестие. Сервер сохраняет режим сеанса меню, а при закрытии восстанавливает исходное состояние игрока. Перемещения камеры, курсора и элементов отправляются одним кадром с одинаковой интерполяцией. Клики и hover проверяются по последнему готовому кадру, пока подготавливается следующий.

## Запустите готовый пример

1. Откройте `plugins/UIcore/cutscenes/demo.yml`. Замените `world` и координаты точек на подходящую площадку своего сервера. Готовый маршрут начинается в `(0, 100, 0)`.
2. Выполните `/uicore cutscene validate`, затем `/uicore cutscene reload`.
3. Откройте `/uicore run demo_cutscene`.
4. Не двигайте мышью во время полёта и поворота. Кнопка **Test moving click** проверяет попадание по видимому элементу во время движения. Когда строка состояния предложит выбор, нажмите **Left route** или **Right route**.
5. Кнопка **Close** закрывает меню и возвращает игрока в исходное положение.

В примере есть плавный маршрут с пользовательской кривой скорости, короткий поворот `179° → −179°`, поворот на месте, пауза и две ветки. Режим `initial` строит меню сразу в первой точке. После завершения меню остаётся открытым в конечном положении. Начальное размещение задано явно и может находиться далеко от места открытия меню.

[Протокол игровых проверок](CUTSCENE_GAMEPLAY_CHECKS.md) отделяет автоматические проверки от проверок, которым ещё нужны Paper, Folia и подключённый клиент. Проверки совместимости неподвижных меню не подтверждают плавность катсцен.

## Подключите отдельный сценарий к меню

Храните каждый сценарий в `plugins/UIcore/cutscenes/<id>.yml`. Поле `id` задаёт его идентификатор. Меню ссылается на сценарий по этому ID:

```yaml
my_menu:
  camera-position: { type: player, distance: 1.5 }
  cutscene: { id: tour, auto-start: true }
  layout:
    start:
      name: "Начать маршрут"
      x: 0
      y: 0
      z: 3.5
      command: ["[cutscene] start tour"]
```

Автозапуск происходит после активации меню. При `auto-start: false` сценарий можно запустить действием элемента или через Java API. Предпросмотр и запуск через API требуют открытого меню.

По умолчанию элемент использует `position-space: camera`: его `x`, `y`, `z` остаются локальными координатами относительно движущейся камеры. Явное `position-space: world` закрепляет элемент по абсолютным координатам в мире меню. Динамические координаты и анимации интерфейса рассчитываются до преобразования камеры. Курсор, наведение и проверка клика используют то же положение камеры, что и отображаемые элементы.

## Задайте точки обзора и движение

Полный пример движения от текущей камеры к точке, ожидания и завершения:

```yaml
id: tour
start: approach
policy:
  start-mode: transition
  transition-ticks: 20
  completion: keep-open
points:
  arrival: { world: world, x: 12.5, y: 75.62, z: -4.0, yaw: 179.0, pitch: 0.0 }
steps:
  approach:
    type: move
    from: current
    to: arrival
    duration: 80
    path: linear
    speed: ease-in-out
    rotation: { mode: interpolate, curve: ease-in-out }
    next: hold
  hold: { type: wait, duration: 40, next: done }
  done: { type: end }
```

Длительности указаны в серверных тиках: при 20 TPS 20 тиков занимают секунду. При снижении TPS катсцена замедляется вместе с сервером, без скачка вперёд для компенсации задержки.

В нужном месте выполните `/uicore cutscene point save tour arrival`. Команда сохраняет текущие координаты **глаз** игрока, yaw и pitch, оставляя остальные поля сценария. Файл заменяется атомарно; запущенные сеансы не меняются. При сохранении в новый файл получается черновик: перед проверкой и загрузкой добавьте `start` и `steps`. Команды точек принимают ID длиной 1–80 символов из латинских букв, цифр, подчёркивания и дефиса.

Команды редактирования точек используют `cutscenes/<scene>.yml`; поле `id` должно совпадать с `<scene>`. Загрузчик также принимает другие имена файлов и расширение `.yaml`; такие файлы редактируются напрямую.

| Поле `move`                       | Назначение                                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------------------- |
| `from`                            | `current` по умолчанию либо ID точки.                                                        |
| `to`                              | ID точки или последовательность, например `[bend, arrival]`.                                 |
| `duration`                        | Положительное число тиков на весь шаг.                                                       |
| `path`                            | `linear` — прямые отрезки; `smooth` — плавная траектория через точки.                        |
| `tangent-before`, `tangent-after` | Необязательные ID точек, задающих касательную перед началом и после конца плавного маршрута. |
| `speed`                           | ID готовой или пользовательской кривой скорости.                                             |
| `rotation`                        | Направление взгляда и отдельная кривая темпа поворота.                                       |
| `next`                            | Явный ID следующего шага.                                                                    |

Для плавного маршрута скорость рассчитывается по пройденному расстоянию, поэтому `uniform` не зависит от внутреннего параметра сплайна. Конечная точка применяется точно. Если промежуточные точки нужно проходить без остановок, объедините их в один `move`. Между соседними шагами используйте `from: current` для сохранения положения камеры. Если именованный `from` не совпадает с фактической позицией и направлением камеры, сценарий прерывается без неявного телепорта.

Чтобы разделить плавный маршрут `A → B → C` в точке `B`, задайте первому шагу `A → B` поле `tangent-after: C`, а второму `B → C` — `tangent-before: A`. Дополнительно согласуйте скорость на стыке: нормализованная скорость кривой в конце/начале × длина маршрута ÷ длительность. Поля касательных согласуют направление, но не скорость. Для `uniform` достаточно одинакового отношения длины маршрута к длительности.

`start-mode: initial` размещает меню с автозапуском в явно заданной начальной точке до активации. Ручной запуск или вызов API в этом режиме требует уже совпадающей камеры открытого меню; иначе подготовка завершается ошибкой. `start-mode: transition` сохраняет текущую камеру и плавно подводит её к явно заданной начальной точке за `transition-ticks`. Используйте `initial` для намеренного начального размещения, а `transition` — для видимого подхода от произвольного открытого меню.

## Переиспользуйте кривые перемещения и поворота

Готовые кривые: `uniform`, `accelerate`, `decelerate`, `ease-in-out`. Перемещение и поворот выбирают кривые независимо. Локальные кривые задаются в сценарии, общие — в разделе `curves:` файла `cutscenes/curves.yml`:

```yaml
curves:
  cruise:
    interpolation: smooth
    points:
      - { time: 0.0, speed: 0.0 }
      - { time: 0.2, speed: 1.0 }
      - { time: 0.8, speed: 1.0 }
      - { time: 1.0, speed: 0.0 }
```

`time` — нормализованное время от 0 до 1. Первая и последняя точки должны находиться в 0 и 1; промежуточные значения строго возрастают. `speed` — конечная неотрицательная относительная скорость. `interpolation: linear` соединяет значения скорости прямыми, `smooth` — плавными неотрицательными участками. Интеграл скорости нормализуется: за длительность шага камера проходит весь маршрут. Нулевая скорость на участке останавливает поступательное движение; полностью нулевая кривая недопустима.

В `rotation.curve` те же точки задают относительную **угловую** скорость. Интегрирование и нормализация имеют ту же семантику, что у перемещения. Точки не задают сам угол или непосредственный прогресс поворота.

## Настройте направление взгляда

| `rotation.mode` | Поведение                                                                                          |
| --------------- | -------------------------------------------------------------------------------------------------- |
| `fixed`         | Сохранить начальное направление либо использовать явные `yaw` и `pitch`.                           |
| `interpolate`   | Плавно перейти к направлению последней точки, с необязательными переопределениями `yaw` и `pitch`. |
| `path`          | Смотреть по касательной к маршруту.                                                                |
| `look-at`       | Смотреть на координаты точки из поля `target`.                                                     |

Для поворота на месте задайте точку с теми же координатами и другими углами. Допустимый `pitch`: `−90..90`. По умолчанию yaw меняется по кратчайшему пути: `179 → −179` — поворот примерно на два градуса. `direction` принимает `shortest`, `clockwise`, `counterclockwise`; неотрицательное целое `turns` добавляет намеренные полные обороты. При совпадении камеры и цели сохраняется последнее корректное направление.

Начальное направление шага должно совпадать с направлением камеры предыдущего шага. Перед переключением на `path`, `look-at` или другое фиксированное направление добавьте интерполированный поворот для выравнивания. Несовпадение приводит к диагностике `steps.<id>.rotation`, а не к скачку камеры.

## Останавливайтесь и принимайте выбор однократно

Шаги имеют уникальные ID и тип `move`, `wait`, `choice` или `end`. Для ожидания по времени укажите `duration: 40`. Для ожидания внешнего продолжения — `duration: external`; переход выполняется после `resume(player)` или команды resume. Ручная пауза посреди движения сохраняет прогресс; продолжение не повторяет действия входа.

```yaml
steps:
  pick:
    type: choice
    options:
      left: { element: left_button, next: left_route }
      right: { element: right_button, next: right_route }
    timeout: 200
    timeout-next: done
    fallback-next: done
  left_route: { type: wait, duration: 20, next: done }
  right_route: { type: wait, duration: 40, next: done }
  done: { type: end }
```

`element` — ID элемента открытого меню. Во время этого выбора клик по элементу автоматически передаёт вариант. У каждого варианта должен быть отдельный элемент. Сохраняются существующие проверки видимости, прав и требований клика; перед принятием варианта они выполняются повторно. API принимает ID варианта (`left`), а не элемента (`left_button`).

Принятие выполняется последовательно на планировщике игрока. Повторный клик или одновременный вызов API с тайм-аутом не запускает две ветки. При заданном `timeout` обязателен `timeout-next`. Если ни один вариант недоступен, выполняется `fallback-next`; без него сеанс прерывается с причиной `NO_AVAILABLE_CHOICE`.

## Выполняйте действия один раз за посещение шага

Списки `enter` и `exit` выполняются при фактическом входе и выходе. Паузы и обновления камеры не повторяют их. Если цикл снова приводит к этому шагу, действия выполняются для нового посещения.

```yaml
enter:
  - "[state] route choosing"
  - "[element-state] status waiting"
  - "[action] quests:show-routes"
  - "[message] Выберите маршрут."
exit:
  - "[element-state] status moving"
```

`[state]` задаёт состояние активного меню только для текущего игрока. `[element-state]` выбирает существующее состояние элемента, включая варианты с `visible: false`. `[action] namespace:id` вызывает зарегистрированное действие UIcore с пустыми аргументами. Остальные строки используют существующие префиксы `[message]`, `[actionbar]`, `[player]`, `[console]` и обычные ограничения безопасности команд.

В списке команд элемента работают `[cutscene] start <id>`, `pause`, `resume`, `skip`, `stop`, `choose <option>`. Зарегистрированные действия и обработчики событий могут вызывать API напрямую.

## Задайте управление и завершение

| Поле `policy`         | Значение по умолчанию и поведение                                                       |
| --------------------- | --------------------------------------------------------------------------------------- |
| `completion`          | `keep-open`; `close-menu` закрывает меню существующим механизмом восстановления игрока. |
| `restart`             | `reject`; `replace` прерывает предыдущую катсцену перед новым запуском.                 |
| `allow-skip`          | `false`; при включении пропуск ведёт в `skip-to` либо завершает сценарий.               |
| `skip-to`             | Необязательный шаг. Действия пропущенных шагов не выполняются.                          |
| `cursor`, `clicks`    | `true`; ввод курсора и клики настраиваются независимо.                                  |
| `edge-pan`            | `false`; включайте только для добавления краевого сдвига к движению по сценарию.        |
| `freeze-ui`           | `false`; обычно анимации и обновления данных интерфейса продолжаются во время паузы.    |
| `chunk-timeout-ticks` | `200`; максимальное ожидание подготовки маршрута.                                       |

Состояния сеанса: `PREPARING`, `PLAYING`, `PAUSED`, `WAITING_CHOICE`, `COMPLETED`, `ABORTED`. Закрытие или смена меню, смерть или выход игрока, отключение плагина и внешний телепорт прерывают активное воспроизведение. Ошибка подготовки или её тайм-аут дают отдельную причину. Проверка поколения сеанса не позволяет отложенной операции старого меню изменить новое.

Катсцена сохраняет неизменяемый снимок конфигурации. `/uicore cutscene reload` заменяет определения только для новых запусков. Проверка `validate` читает файлы, не меняя сеансы и загруженные определения. `/uicore reload` также перезагружает остальную конфигурацию UIcore; для изменения только сценариев используйте отдельную команду катсцен.

Подготовка ограничена 4096 чанками и 100 000 участками маршрута на сценарий. Разделите более длинный маршрут на несколько сценариев. При превышении лимита подготовка завершается с диагностикой, ограничивая нагрузку одного запуска.

## Используйте административные команды

| Команда                                                       | Право                                         |
| ------------------------------------------------------------- | --------------------------------------------- |
| `/uicore cutscene point save <scene> <point>`                 | `uicore.cutscene.edit`; только игрок.         |
| `/uicore cutscene point list <scene>`                         | `uicore.cutscene.edit`.                       |
| `/uicore cutscene validate`                                   | `uicore.cutscene.edit`.                       |
| `/uicore cutscene reload`                                     | `uicore.cutscene.edit`.                       |
| `/uicore cutscene preview <scene> [player]`                   | `uicore.cutscene.preview`; `start` — синоним. |
| `/uicore cutscene stop\|pause\|resume\|skip\|status [player]` | `uicore.cutscene.preview`.                    |

Оба права по умолчанию доступны операторам и выдаются независимо. Консоль должна указывать игрока в командах воспроизведения. `/ui` — синоним `/uicore`. Предпросмотр требует открытого меню и использует обычный путь воспроизведения.

Проверка обнаруживает неизвестные точки, кривые и переходы, неверные длительности и углы, ошибки вариантов и мгновенные циклы без движения, ожидания или ввода. Диагностика содержит ID сценария, шага и путь параметра, например `Cutscene 'tour', step 'approach', path 'steps.approach.to': ...`.

## Управляйте катсценой через Java

```java
UIcoreApi api = UIcoreProvider.get();
CutsceneStartResult result = api.cutscenes().start(player, "tour");
// ACCEPTED подтверждает запрос. Начало воспроизведения — CutsceneStartEvent.
api.cutscenes().pause(player);
api.cutscenes().resume(player);
api.cutscenes().choose(player, "left");
api.cutscenes().state(player).ifPresent(snapshot -> {
    String step = snapshot.stepId();
    double progress = snapshot.stepProgress();
    long ticks = snapshot.elapsedTicks();
});
api.cutscenes().stop(player);
```

Типы находятся в `org.orvencraft.uicore.api.cutscene`. Результаты запуска: `ACCEPTED`, `UNKNOWN_SCENE`, `NO_MENU`, `ALREADY_RUNNING`. При передаче вызова другому планировщику возвращаемое значение подтверждает возможность поставить запрос в очередь; фактический результат подготовки и принятия выбора определяйте по снимку или событию.

В пакете `org.orvencraft.uicore.api.event` доступны `CutsceneStartEvent`, `CutsceneStepEnterEvent`, `CutscenePauseEvent`, `CutsceneResumeEvent`, `CutsceneChoiceEvent`, `CutsceneCompleteEvent`, `CutsceneAbortEvent`. Все содержат игрока, ID сценария и снимок. Выбор добавляет `getOptionId()`, прерывание — `getReason()` и `getDiagnostic()`. События выполняются на планировщике игрока, который в Folia может быть потоком региона. Для работы с другими сущностями и миром используйте их собственные планировщики.

Снимок содержит ID сеанса и сценария, состояние, ID шага, прошедшие тики всего сценария и шага, нормализованный прогресс шага. Подготовка и ручная пауза не продвигают время движения.
