# Следующие задачи UIcore

> **Язык:** [English](PLANNED_TASKS.md) | Русский

Задачи записаны по обсуждению. Базовая реализация пунктов 2 и 4 готова; перенос 3 находится на этапе игровой проверки. Перетаскивание и интерактивное вращение удалены из 1.0.0; их возможное возвращение остаётся идеей.

1. Перетаскивание группы и интерактивное вращение элемента удалены из 1.0.0. Сроков возвращения этих жестов пока нет.
2. Состояния отдельных элементов: нажатие другого элемента меняет state, который управляет показом, скрытием и оформлением. Базовая реализация готова: `initial-state`, `states`, `set-state` и `set-states`; значения хранятся отдельно для каждого игрока и очищаются при закрытии меню. Существующие permission conditions сохранены. Пример: `demo_states.yml`.
3. Совместимость Minecraft 1.21.1 и новее на Paper, Folia, Purpur и доступных сборках Leaf: один JAR собирается против API 1.21.1 с bytecode Java 17. Проверка меню с подключённым игроком и дополнительных интеграций ещё нужна; результаты — в [матрице совместимости](COMPATIBILITY_RU.md), подробности Folia — в [статусе порта](PORT_26_2_RU.md).
4. Папка `plugins/UIcore/schematics/` для схем. Базовая реализация читает Sponge `.schem` v2/v3, привязывает до четырёх схем к меню и позиции, отправляет одному игроку пакетные изменения блоков и восстанавливает актуальные блоки при закрытии/смене меню. Формат и лимиты описаны в [справочнике](MENU_AUTHORING_GUIDE_RU.md). Содержимое block entities, сущности и биомы пока не показаны; крупные схемы требуют игровой проверки.

Идеи для ввода в меню:

- Свободное перемещение списка элементов как одной группы и вращение одного выбранного элемента — разные жесты. Оба могут присутствовать в одном меню: тип действия определяется элементом, на котором игрок начал удерживать ЛКМ. Для вращения нужен отдельный элемент управления со ссылкой на целевой элемент. Во время любого перетаскивания видимый курсор остаётся на месте; после завершения продолжает движение с сохранённых координат.
- Позже добавить прокрутку меню вверх и вниз колёсиком мыши. Источник ввода — смена выбранного слота среди невидимых предметов хотбара. Пока это только идея, без реализации.

## Адаптеры после стабилизации UIcore 2.0

Запланированы отдельные адаптеры для MMOcore, BetonQuest, Quests и JobsReborn. К реализации пока не приступать.

Vault и LuckPerms встроены в UIcore как необязательные интеграции. Источники данных и условия описаны в [руководстве](BUILTIN_INTEGRATIONS_RU.md). Операции списания и начисления денег пока не добавлены.

Перед реализацией определить минимальные версии зависимостей, возможности их API и правила выполнения вызовов на Paper/Folia.
